# 44. 셀프 체크인 — 제품 요구사항(PRD)

> 상태: **초안(2026-10-30) · 사용자 검토 대기 · 코드 미착수.**
> 결정 기록(왜 이렇게 정했나)은 `43-self-checkin-kiosk.md`, 기술 설계(어떻게 만드나)는 `../engineering/16-self-checkin-technical-design.md`.
> 이 문서는 **무엇을 · 누구를 위해 · 어느 수준까지** 를 요구사항 문장으로 고정한다. 요구사항 ID(FR · NFR · AC)는 QA · 롤아웃 · 시안이 참조한다.

## 1. 배경 · 문제 · 목표

### 1-1. 배경
- 회사는 신주쿠구 여관업법 허가 건물 8곳(객실 약 68개)을 운영한다. 체크인은 각 건물 1층의 회사 소유 Android 태블릿에서 손님이 직접 하며, 지금은 **Hotelsmart**(월 구독 PMS)의 태블릿 화면을 쓴다.
- 예약은 Beds24 가 원본이고 Foldy 가 이미 웹훅으로 받는다. 청소 배정 · 근태 · 급여 · 판매 캘린더는 Foldy 로 옮겨 왔고, **체크인만 Hotelsmart 에 남아 있다**(01 결정 2026-10-21).
- 회사 의뢰(2026-10-29): 태블릿 셀프 체크인을 Foldy 쪽에 만들어 달라.

### 1-2. 문제
1. **두 시스템**: 예약 · 청소 · 직원은 Foldy, 명부 · 체크인은 Hotelsmart — 「오늘 누가 체크인했나」를 Foldy 에서 못 본다. 청소 현황판 · 대시보드와 이어지지 않는다.
2. **명부 품질이 건물마다 다르다**: Hotelsmart 필수 칸 설정이 건물별로 달라 법 요건(국적 · 여권 번호)이 빠지는 건물이 있다(43 §8-6(4)).
3. **손님이 직접 치는 칸이 많다**: 로마자 이름 · 여권 번호 · 생년월일을 손으로 입력 → 오타 · 시간 · 포기.
4. **비밀번호가 도착 전에 나가므로** 태블릿을 건너뛰는 손님이 생기는데, 미체크인 손님을 직원이 한눈에 보는 화면이 없다.
5. 구독 비용과 벤더 종속(약관상 자동 연동 금지 — 01 결정 2026-10-06).

### 1-3. 목표(이 제품이 끝났을 때 참인 것)
- G1. 손님은 **직원 없이** 4개 언어 태블릿에서 법 요건을 만족하는 명부 · 여권 사본 · 본인 확인을 **3분 안에**(2인 기준) 끝낸다.
- G2. 직원은 Foldy 에서 **오늘 도착 중 누가 체크인했고 누가 안 했는지**, 명부 · 여권 · 동영상을 보고 「확인함」을 남긴다.
- G3. 명부 · 여권 · 동영상은 **3년 보관 · 자동 삭제 · 열람 기록**으로 법 · 개인정보 요건을 만족한다.
- G4. 전 건물에서 Hotelsmart 체크인을 끈다(해지는 별도 결정).
- G5. 기존 Foldy 에 **아무 영향도 주지 않는다**(43 §8-9 절대 조건).

### 1-4. 목표가 아닌 것(이번 범위 밖)
- 직원 상주 · 긴급 출동 체계(사용자 지시). 결제 · 정산(OTA 선결제). 스마트락 연동. 셀프 체크아웃. iOS 태블릿. 여권 NFC(2차 조건부). 직원 영상 통화 · 자동 얼굴 대조(설정 자리만). Hotelsmart 명부의 DB 이관(파일 보관만). 다른 회사 판매(구조만 열어 둠).

| --- | --- | --- | --- |

## 3. 범위

- **들어감**: 태블릿 앱(Android 네이티브) · 손님 사전 등록 웹 · 서버 API · `checkin` 스키마 · Foldy 직원 화면(PC · 모바일) · 권한 키 3개 · 보존 · 감사 · 기기 관리 · 건물 설정 · Beds24 예약 읽기 동기화 · 리마인드.
- **안 들어감**: §1-4.

## 8. 사용자 여정

### 8-1. J1 해피 패스 — 외국인 2명, 사전 등록 없음(목표 3분)
```txt
언어 선택(5초) → 코드 입력(15초) → 방 · 인원 확인(10초)
→ 사람 1: 여권 촬영(15초) → MRZ 자동 채움 확인 · 주소 · 연락처(40초)
→ 사람 2: 여권 촬영(15초) → 확인(20초)
→ 약관 동의(15초) → 얼굴 동영상 10초 → 완료 화면(방 · 비밀번호, 30초 뒤 처음)
합계 약 2분 45초
```
### 8-2. J2 사전 등록 손님(목표 1분)
```txt
언어 → 코드 → 입력 내용 요약 확인(사람별 ✓) → 동영상 → 완료
```
### 8-3. J3 단체 5명 · 어린이 1 · 방 2개
```txt
코드 → 방 2개 화면에서 사람 배정 → 사람별 탭 5개(아이는 「여권 없음」 체크) → 동의 → 동영상 25초 → 완료(방 2개 번호 · 비밀번호)
```
### 8-4. J4 일본 거주자
```txt
코드 → 「일본에 주소가 있어요」 → 이름 · 주소 · 연락처만 → 동의 → 동영상 → 완료
```

## 11. 수용 기준 (AC) — 「완료」의 정의
- AC-01 (FR-K02 · K03) 코드 · 이름으로 찾기 — 가능 기간 안 예약은 찾고, 전 · 후 · 취소 · 다른 건물은 사유 문구. 자동 테스트 + 실기기.
- AC-02 (FR-K07) 여권 10개국 샘플 ≥ 9 자동 채움 성공, 체크섬 실패는 「확인 필요」 표시.
- AC-03 (FR-K10) 2명 → 10초 동영상 파일이 서버에 저장되고 직원 화면에서 재생.
- AC-04 (FR-K12 · K15) 입력 중 와이파이 끄기 → 240초 → 켜기 → 같은 코드로 다시 찾기 → 이어서, 서버에 중복 없음.
- AC-05 (FR-D02) 재부팅 뒤 60초 안에 첫 화면 복귀, 홈 · 뒤로 버튼 무반응.
- AC-06 (FR-W01~03) 링크로 전원 입력 → 태블릿에서 「요약 확인 → 동영상」만, 체크인 뒤 링크는 읽기 전용.
- AC-07 (FR-S01 · S02) 오늘 도착 8건 중 체크인 3 · 진행 중 1 · 미체크인 4 가 PC 에서 정확히, 패널에서 여권 · 동영상 열람 시 `audit_log` 1줄.
- AC-08 (FR-S09) 권한 없는 사무실 직원은 `/admin/checkin` 접근 불가(서버 액션도 forbidden), 개인 부여 뒤 가능.
- AC-09 (FR-B03) `retain_until` 지난 테스트 자료가 새벽 작업 뒤 파일 · 줄 모두 없고 `deletions` 1줄.
- AC-10 (NFR-09) 1~5단계 각 끝에 루트 `npm run lint` · `npm run build` 통과, `git diff --stat` 에 Foldy 기존 파일 변경 없음(루트 두 줄 제외).
- AC-11 (FR-K01 · NFR-08) 4개 언어 전 화면 스크린샷, 긴 문구(en · zh) 잘림 없음.
- AC-12 (FR-K11 · K04) 완료 뒤 30초 처음으로, 다시 찾으면 비밀번호 다시 보기.

### 14-5. D1 — Beds24 자동 메시지가 안 될 때의 대비 (2026-10-30, 사용자 「만약 베드24에서 안 된다면?」)

안 될 수 있는 경우: 우리 계정에 Airbnb · Booking.com **메시지 API 연결이 안 켜져 있음**, 채널 정책으로 링크가 가려짐, Info 항목이 템플릿에 안 들어감, 배치 지연.

**대비 설계 — 「메시지에 개인별 값이 없어도 되게」 만든다.** 사전 등록 입구를 **건물별 고정 공개 링크**(`checkin.<도메인>/p/kabukicho`, QR 도 같은 값)로 두고, 손님이 **이름 + 체크인 날짜 + 전화 뒤 4자리(또는 Airbnb · Booking.com 예약 번호)** 로 본인 예약을 찾으면 그때 토큰이 발급돼 개인 폼이 열린다. 태블릿도 이름 + 날짜로 찾으므로 **6자리 코드는 「있으면 빠른 길」일 뿐 필수가 아니다**(사전 등록 완료 화면과 QR 에서 받음).
