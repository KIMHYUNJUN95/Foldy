# 37 · 시프트 신청 · 청소 배정

> 상태: **기능 구현 완료 (2026-10-23, 사용자 확정)** — 기획 · 시안 6개 확정(2026-10-20) 뒤 구현(2026-10-21), 다듬기 · 추가(10-22~23) 뒤 전체 디버깅 통과. 실제 구조는 「10. 구현」.
> 배포: 남은 커밋은 **나중에 한 번에**(사용자 지시 2026-10-23). 남은 것: 실제 알바 데이터로 동작 확인 · 알림(막바지 일괄) · 처음 2주 한 건물 Hotelsmart 병행(6번).

## 1. 왜 만드나

지금 청소 배정은 외부 서비스 **Hotelsmart** 에서 한다. Hotelsmart 는 원래 **무인 체크인**(건물 앞 태블릿 · 여관업법상 숙박자 명부 ·
본인 확인) 때문에 쓰는 서비스이고, 청소 배정은 거기 딸린 부가 기능이다.

- **청소 쪽에서 실제로 쓰는 것은 하나** — 그날 시프트를 신청한 알바생을 그날 체크아웃 객실에 배정하는 것.
- 청소 완료 상태는 Hotelsmart 에서 다루지 않는다. 외부 API 도 없다(우리가 쓰는 외부 API 는 Beds24 하나).
  → **청소 배정을 끊어도 체크인 쪽에 영향이 없다.**
- 문제: 쓰기 불편하고 버그가 많다. 알바생마다 **개인 시프트 URL** 을 만들어 주고, 각자 그 페이지에서 가능한 날을 신청하면,
  관리자가 본계정에서 신청자를 하나씩 방에 배정한다. **이 구조는 따라 하지 않는다.**
- Foldy 에는 재료가 이미 있다: 오늘 청소할 방(퇴실 기준) · 수기로 더한 방(`cleaning_list_extra_rooms`) · 현장 청소 타이머/기록 ·
  Slack 청소 · 셋팅 명단(`docs/product/36-automation-control.md` ②) · 출근 기록. 빠진 것은 **「누가 언제 나오나」와 「누가 어느 방」** 둘이다.
  지금 Slack 명단 담당자는 사람이 손으로 넣는다(`cleaning_list_assignees`, Hotelsmart 약관상 자동 수집 안 함).

### 범위 밖

- 무인 체크인 · 숙박자 명부 · 본인 확인 — **Hotelsmart 그대로**.
- Hotelsmart 와 데이터 주고받기 — API 가 없으므로 하지 않는다.

## 2. 지금 일하는 방식 (사용자 확인 2026-10-20)

| 근무 형태 | **시프트제** — 희망 휴무가 아니라, 알바생이 **일할 수 있는 날을 날짜마다 신청**한다 |

| 배정 방식 | 그날 시프트 신청자에게 그날 체크아웃 객실을 **균등하게** 나눈다. 유동적이라 **방을 수기로 추가해서 배정**하는 경우도 있다 |

| 취소 | 신청과 똑같이 날짜를 다시 눌러 취소. 단 **배정받은 방이 있으면 스스로 취소 못 함 → 관리자 확인** |

| 신청자가 넘칠 때 | 따로 메모해 둔 **일 잘하는 고정 인력 · 출근을 많이 해 주는 고정 인력을 먼저** 배정. 선착순보다 **관리자 판단**이 훨씬 많다 |
| 확정 | **배정하면 곧 확정**이다 — 확정 단계가 따로 없다 |
| 배정 담당 | **여러 명** — 건물마다 2명 정도. 대표(사용자)는 모든 권한 |
| 이번 달 추가 | **언제든** 신청 · 배정. 하루 예약이 수십 건이라 전달 말에 다 배정해도 **다음 날부터 또 추가 배정**이 생긴다 |
| 배정 시각 | 늦으면 **밤 11시까지** 다음 날 청소를 배정한다 |
| 청소 원칙 | **체크아웃한 방은 다음 체크인이 없어도 당일 청소.** 아주 가끔 너무 바쁘고 사람이 없으면 예외(미룸) |
| 셋팅 | **배정 대상 아님** — 셋팅 방은 Slack 자동 메시지로 이미 나간다 |
| 한 방 여러 명 | 큰 방에 **2~3명** 투입이 많다 |
| 신입 | 일정 횟수는 **현장 매니저나 견습 담당과 같이** 투입. 견습 몇 번째인지 · 어느 건물을 가 봤는지 보여 주는 기능이 필요 |
| 담당 건물 | 배정 담당은 **전 건물을 고칠 수 있다.** 다만 누가 어느 건물을 **메인**으로 맡는지 틀이 있고, 휴무 · 연차 · 주말엔 서로 돕는다 |
| 급여 비교 | 알바 급여와 방 개수가 **연결돼 보이면 좋다** — 방을 많이 했는데 월급이 적거나, 적게 했는데 높으면 의심할 만한 신호 |
| 동료 보기 | 알바는 같은 날 동료 이름 · 방을 볼 수 있으면 좋다. **단 모든 날짜는 안 된다** — 배정을 많이/못 받았다는 불만 · 논쟁이 생긴다. 관리자(대표가 권한 준 사람)는 전부 |
| 출근 시각 | 보통 **알바 9:45 · 직원 9:00.** 특정 인원은 사정마다 조금씩 다르다 |
| 대신 넣기 | 필요 — 급한 건, 앱 쓰기 어려운 사람 |
| 당일 취소 | 이미 출근했으면 **다른 사람 방에 붙여 돕게** 하고, 아직 출근 전이면 **그날 일정이 취소**될 수 있다. 지금은 알림보다 **관리자가 바로 연락**. 알림은 막바지에 붙이면 좋다 |
| 신청 인원 | 하루 시프트 신청자가 **수십 명**. Hotelsmart 는 누가 어디 배정됐고 누가 아직인지 표시가 없어 신청자 목록과 객실을 **하나하나 대조**한다 — **여러 명이 들어가는 큰 방에서 가장 불편** |

## 3. 핵심 아이디어 — 배정 = 확정, 대신 「제안」을 Foldy 가 만든다

확정 단계를 따로 두지 않는다(사용자 확인 2026-10-20) — **방을 배정받은 날이 곧 확정된 날**이다. Hotelsmart 에서 시간이 드는 것은
「신청자 확인 → 방 하나씩 붙이기」를 날짜마다 반복하는 일이므로, 그 반복을 Foldy 가 대신 한다.

- **자동 제안**: 날짜마다 그날 신청자에게 그날 방을 나눈 안을 만든다. **고르는 기준은 관리자가 정한다**(4-5 배정 설정 —
  규칙을 켜고 끄고 순서를 바꾸기 + **건물별 1 · 2 · 3순위 고정 인력**). 처음 값은 고정 인력 먼저 → 배정 전 · 방 적은 사람 먼저(균등) →
  「우선 배정」 표시 먼저 → 같은 건물끼리. 「우선 배정」 표시 + 비공개 메모는 지금 따로 적어 두는 메모를 대신한다.
- **관리자는 고친다**: 제안을 그대로 쓰거나, 끌어다 옮기거나, 사람을 빼거나 더한다. 저장하면 그 배정이 곧 확정.
- **월말 한 번에**: 다음 달 전체를 한 화면에서 제안 → 날짜별로 훑어보고 → 반영. 반영은 **미배정 방만 채운다**(이미 배정된 방은 건드리지 않음).
- **매일이 본업**: 하루 수십 건 예약이 들어오므로 월말 배정은 출발점일 뿐이다. 새로 들어온 퇴실 · 수기 추가 방은 **「미배정」으로 위에 뜨고**,
  그날 방이 가장 적은 신청자에게 넣는 안을 바로 보여 준다(누르면 한 번에 배정). 취소로 사라진 방은 배정에서 빠지고 표시만 남는다.
  사람이 이미 손댄 배정은 자동으로 다시 섞지 않는다.
- **대상은 체크아웃 방(+ 수기 추가)만** — 셋팅은 제외. 체크아웃 방은 다음 체크인이 없어도 당일 청소가 원칙이라 전부 대상이다.
- **청소 안 된 방은 저절로 사라지지 않는다**(객실이 많아 놓칠 수 있다). 그날 끝까지 청소 안 된 방은 **다음 날 미배정 맨 위**에
  「어제부터 · N일째」 표시로 다시 뜬다. 처리 방법은 셋 중 하나:
  1. **미룸(다음 날)** — 사유 한 줄. 다음 날 미배정 맨 위.
  2. **날짜 정해 미루기** — 사정이 있어 당장 안 할 때. 고른 날까지 목록에서 빠졌다가 그날 미배정 맨 위로 돌아온다.
  3. **강제완료** — 청소가 필요 없게 됐을 때. 지금 PC 청소 대시보드의 강제완료(`cleaning.force_complete`)와 같은 기록으로 남긴다.
- **1인 방 수와 하루 몫**: 사람마다 그날 방 수를 보여 주고, 작은 방 1 · 큰 방(보통 인원 2명 이상) 1.5 · 한 사람 상한 3(2인 큰 방은 각자 1.5)을 제안(하루 · 월 · 「고정 인력 먼저」)이 지킨다 — 이미 넣은 방도 몫에 넣고, 넘는 방은 미배정으로 두고 「사람 모자람 · N개 남음」. 직접 넣기(사람 넣기 · 방 추가 · 교체 · 모바일 담당 넣기)는 막지 않고 같은 확인 창만. 건물별 「보통 몇 개」는 제안의 기준으로 그대로 쓴다(Q3 · 문서 45 L1~L6).

## 4. 화면 (초안)

### 4-1. 시프트 신청 — 모바일 (알바생)

- 개인 URL 없음. **Foldy 앱에 로그인한 그대로** 「내 시프트」에서 달력을 열고 일할 수 있는 날을 누른다. 다시 누르면 취소.
- **「신청하기」 토글(2026-10-22 사용자 지시 · 시안 https://claude.ai/artifact/V9NDwfEp1GQZG2BiPC9yXs):** 누르면 바로 끝나서 「신청한 느낌이 없다」 →
  제목 아래 「신청하기」 스위치를 **켰을 때만** 날짜를 눌러 신청 · 취소한다(완료 버튼 없음 — 누르는 즉시 저장). 들어올 때마다 꺼진 채 시작.
  - 꺼진 채 신청 안 한 날을 누르면 신청하지 않고 줄이 옅은 보라로 깜빡 · 스위치가 흔들리며 「신청하려면 먼저 켜 주세요」(경고 진동).
    배정된 날은 토글과 상관없이 눌러서 방 · 출근 시각을 본다(배정된 날은 눌러도 취소되지 않음).
  - 켠 동안: 아직 신청 안 한 앞날에 아주 옅은 원, 넣으면 원이 12시부터 한 바퀴 그려지고 숫자가 톡(중간 진동), 빼면 원이 줄며 사라짐(가벼운 진동).
    스위치 아래 「12월 신청 N일 · 누르면 바로 저장돼요」 — 숫자가 누를 때마다 넘어간다(일한 날 · 배정 · 배정 전 · 배정 없음을 센다).
  - 끄면(그 사이 하나라도 바꿨으면) 탭바 위에 「12월 신청 N일 · 저장돼 있어요」 토스트(체크 그리기, 공용 `useToastMotion`, 2.6초).
  - 움직임 줄이기 설정이면 움직임 없이 상태만 바뀐다.
  **빠르게 연달아 눌러도 된다(2026-10-22 사용자 지시):** 누르는 즉시 원이 바뀌고 달력을 잠그지 않는다. 저장은 누른 순서대로 줄 세워 보내고
  (`toggleMyShift({ date, apply })` — 바라는 상태를 보내 같은 날을 여러 번 눌러도 마지막 상태로 맞춤), 다 끝나면 한 번만 새로 불러온다.
  새 데이터가 올 때까지 표시를 그대로 둬서 원이 깜빡이지 않는다. 실패한 날만 원래대로 돌리고 안내를 띄운다.
- 날짜 상태: 신청 · **배정됨(= 확정, 방 수 표시)** · **배정 없음**(신청했지만 그날 방이 없음 — 확실히 보여 줘야 헷갈리지 않는다).
  배정은 전날 밤 11시까지도 바뀌므로 **다음 날 몫은 바뀌는 즉시 화면에 반영**한다(정할 것 Q13-b).
- **배정된 날은 스스로 취소할 수 없다** — 누르면 「취소 요청」이 관리자에게 가고, 관리자가 받아 주면 그 방들은 「미배정」으로 돌아간다.
  취소 요청은 **실제로 배정된 날**(그 사람 · 그날 `cleaning_assignments` 가 있음)이고 관리자가 취소하지 않은 신청(`cancelled_at is null`)에만 걸린다(2026-10-26 — 배정 전 · 취소된 날에 요청이 들어가던 것 수정). 요청 거두기는 배정이 빠진 뒤에도 된다.
  **유령 배정은 배정이 아니다(2026-11-09, 문서 45 C14):** 그날 청소할 방 목록에 없는 배정(배정 뒤 예약 취소 · 날짜 변경)만 남은 날은 달력에 방 수가 없고,
  눌러서 신청을 뺄 수 있으며(남은 배정 줄은 지우지 않음 — 관리자가 「취소됨」 방에서 정리) 취소 요청은 걸리지 않는다. 서버 `toggleMyShift` · `requestShiftCancel` 이
  달력과 같은 판단을 서버 공용 `loadLiveAssignmentsOfDay`(`src/lib/cleaning-assign/live-day.ts` — 체크인 정보는 읽지 않음)로 쓰고, 관리자 월 칸 신청 빼기
  (`toggleApplicationForUser`)도 같은 함수다(유령 배정만 있으면 신청을 뺀다, 2026-11-09 리뷰). 지난 날은 목록을 읽지 않아 판단하지 않는다.
  **기록 있는 배정은 유령이 아니다** — 그 사람이 그날 그 방에 진행 중 · 완료 기록이 있으면 목록에 없어도 배정으로 센다(지난 날 비교표 · 사람 달력에서 실제 청소한 방이 빠지지 않게).
- **마감 없음**(Q1-b): 이번 달 · 다음 달 모두 언제든 신청 · 취소(배정 전). 다음 달 달력은 늘 열려 있고, 월말이 다가오면(20일부터)
  「다음 달 시프트를 월말까지 신청해 주세요」 한 줄만 보여 준다 — 막지 않는다.
- 배정된 날에는 **그날 출근 시각**이 같이 보인다(4-2-b).
- 화면(2026-10-22 HIG 다듬기로 바뀜 — 아래 「모바일 HIG 다듬기」): 오른쪽 위 「11월 신청」(20일부터) → 큰 제목 「내 시프트」 + 「11월 신청은 월말까지 · N일 남음」 →
  「다음 근무」 한 줄 → 달력(제목 왼쪽 · 화살표 오른쪽).
  날짜 칸 = **채운 보라 원 + 「2방」(배정) · 옅은 보라 빈 원(신청 · 배정 전) · 흐린 숫자 + 「없음」(배정 없음) · 흐린 숫자(지난 날 · 일한 날)** — 범례 없이 모양 + 글자로 구분.
  (처음 시안은 연보라 · 연노랑 · 연회색 칸 + 색 설명 줄이었다.)
- **「배정 없음」 기준**(사용자 확인 2026-10-20) — 신청했는데 방이 없다고 바로 「배정 없음」이 아니다(그건 「신청 · 배정 전」과 같다). 다음 중 하나일 때만:
  1. 그날 **미배정 방이 0** — 체크아웃 방이 전부 배정돼 더 받을 방이 없다.
  2. 관리자가 그 사람 그날 일정을 **취소**했다(4-2-d).
  3. 그날이 **지났다**.
  1 의 상태에서 새 예약 · 수기 추가로 미배정 방이 다시 생기면 「신청 · 배정 전」으로 되돌아간다.
  아래 「다가오는 일정」(「다음 근무」에 올린 날은 빼고 — 9:45 · 방 1개 / 신청함 · 배정 전 / 배정 없음 — 나오지 않아도 돼요).
  배정된 날을 누르면 바텀 시트(공용 `BottomSheet`) — 출근 시각 · 방 · 같이 일하는 사람 · 「취소 요청」. 폴드 = 왼쪽 레일, 태블릿 = 사이드바 + 오른쪽 그날 칸.

### 4-2. 배정 — PC (관리자, 월 단위 + 매일)

- **월 보기**: 날짜 × 사람 표(한 달 30열). 칸 = 점(신청만 함) / 옅은 보라 숫자(배정 · 방 수) / 보라 테두리 숫자(제안, 반영 전).
  표 위 세 줄 — **청소 방(예약 기준) · 신청 · 미배정 방**. 신청자가 모자란 날은 빨간 숫자. 사람 줄 오른쪽에 그달 방 수 합계,
  이름 옆에 고정 순위 · 우선 · 견습. 날짜를 누르면 그날 하루 보기, 칸을 누르면 그 사람 그날 방.
- **「11월 자동 제안」** → 표에 제안이 테두리 칸으로 깔리고 위에 한 줄 — 「미배정 방 412개 중 388개를 채워요 · 이미 배정된 방은 그대로 ·
  사람이 모자란 날 3일 — 24개 남아요」 → [취소] [388개 반영]. 반영은 **미배정 방만** 채운다(4-2-f). 제안 기준은 4-5 배정 설정.
  미리 보기는 **미리 본 달에서만** 보인다 — 다른 달로 넘기면 사라지고, 돌아와도 다시 보이지 않는다. 반영은 미리 본 달로 보낸다(2026-11-09, 문서 45 A13 — 예전엔 달을 바꿔도 남아 다른 달 반영 버튼처럼 보였다).
  제안 대상은 그날 신청한 **현장 멤버만** — 비활성 · 조직에서 빠진 사람의 신청 줄은 제안하지 않는다(하루 · 월 · 「고정 인력 먼저」 같음, 문서 45 A11).
- **하루 보기**: 왼쪽 그날 청소할 방(퇴실 + 수기 추가, 미배정이 위 — **미배정도 건물별 묶음 · 객실 번호 순**, 건물 이름은 묶음 제목에 한 번, 2026-10-21 사용자 지시. 방마다 체크인 한 줄 — 체크인 있는 방은 「오늘 체크인 N명 · 고객명」, 없는 방은 「다음 체크인 날짜 · N명 · 고객명」, 30일 안에 없으면 「체크인 없음」. 수기 추가 · 못 한 방도 예약에서 찾아 채운다 — 2026-10-21 사용자 지시. 「오늘 내 방」도 같은 줄. 위쪽 날짜 고르기 달력은 조금 크고 **날짜마다 미배정 방 수**를 빨간 숫자로(오늘부터 · 월 보기 미배정과 같은 기준 · 0 이면 없음, 2026-10-21 사용자 지시)), 오른쪽 그날 신청자별 칸(우선 배정 표시 · 그날 방 수).
  끌어다 놓기 · 「자동 제안」 · 사람 빼기. 신청 안 한 사람도 관리자가 넣을 수 있다(대신 신청, Q6).
- **넣기 · 빼기(2026-10-23 사용자 지시 「뺄 때 UI 가 불편해, 넣고 빼고가 직관적으로」 · 시안 https://claude.ai/artifact/Evr8xVkWpHhpNtg5NCgrU1):**
  - 평소: 방 안 **이름표**(이니셜 원 + 이름)에 마우스를 올리면 ×, 누르면 바로 빠지고 아래 **5초 「되돌리기」**(다시 넣기). 터치 화면은 × 가 늘 보인다.
  - 빈 방 · 인원이 모자란 방: **「+ 사람」**(1명 이상 있으면 「1명 더」) → 작은 창 — 그날 신청한 사람 중 그 방에 없는 사람, **배정 전이 위**(방 적은 순), 제안된 사람은 「제안」.
    미배정 방에 「제안 · ○○ 넣기」가 있으면 「+」는 아이콘만(다른 사람을 고를 때).
  - 사람을 고르면: 방 줄 왼쪽 **체크 원** — 줄 아무 데나 누르면 그 사람을 넣기 ↔ 빼기, 넣은 방은 원이 보라로 채워지며 체크가 그려지고 줄이 옅은 보라. 오른쪽 작은 글자 「넣기 / 빼기」.
    (전에는 방마다 「+ 넣기」 · 「빼기」 버튼 — 빼려면 사람을 먼저 고르고 그 사람 방을 찾아 내려가야 했다.)
  - 넣기는 대기 방만, 빼기는 기록 없는 사람만(문서 45 표 2, 2026-11-04 — `canAddPerson` · `canRemovePerson`). 청소 중 · 끝난 방에서 기록 없는 사람은 × 로 뺄 수 있고 되돌리기는 없다(시작한 방엔 다시 못 넣음). 미룸 · 처리 끝 방은 × · + · 체크 원이 없다. 저장은 그대로 방 한 건씩(`assignToRoom` · `unassignFromRoom`).
- **방 수기 추가**: 지금의 `cleaning_list_extra_rooms`(퇴실 없는 연박 청소 등)를 그대로 쓴다 — 추가한 방도 배정 대상.
  위 「+ 방 추가」 → 작은 창(건물 · 방 · 메모(선택) · **바로 넣을 사람(선택, 여러 명)**) → 「추가하고 넣기」. 사람을 안 고르면 미배정 맨 위에
  「직접 추가 · 추가한 사람」 표시로 들어가 다른 방처럼 제안 · 넣기를 받는다.
- **취소 요청함**: 배정된 사람이 보낸 취소 요청 → 받아 주기 / 돌려보내기.
  신청자 줄 모양(2026-10-23, 시안 https://claude.ai/artifact/8siDG3e1ANmnyCW7xMtvaD A안): 상자 없이 빨간 점 + 「취소 요청 · 메모」 한 줄, 아래 알약 칩
  [받아 주기](옅은 빨강) [돌려보내기](회색). 「아직 견습인가요?」도 같은 모양(주황 점 · [견습 끝](보라) [계속 견습]). 오른쪽 「일정 취소」는 평소 회색 글자 · 올리면 빨강.
- **사람 메모**: 사람마다 「우선 배정」 켜기 · 비공개 메모(관리자끼리만 본다).
- **메인 건물**: 담당자마다 메인 건물을 정해 두면 보드가 처음엔 **내 건물만** 보여 준다. 「전 건물」로 바꾸면 다른 건물도 바로 고칠 수 있다
  (권한으로 막지 않는다 — 휴무 · 연차 · 주말에 서로 돕는다). 오늘 미배정 방이 남은 건물은 다른 담당자 화면에도 표시.
  「제안대로 N개 넣기」 · 「고정 인력 먼저 넣기」는 **보이는 건물만** 넣는다 — 화면이 거르기 범위를 보내고 서버(`applyDaySuggestions` `properties`)가 같은 범위로 거른다.
  버튼의 N = 실제로 넣는 수(2026-11-09, 문서 45 A12 — 예전엔 「내 건물」만 보여도 전 건물에 넣었다).
  건물 고르기 창(「전체 건물 ⌄」)은 창 바깥을 누르거나 Esc 면 닫힌다(저장 없이 — 2026-10-22).
- 결과가 **Slack 청소 명단 담당자**로 그대로 나간다 → `cleaning_list_assignees` 수기 입력이 없어진다(셋팅 명단은 지금 그대로).

- 위 줄에 **「고정 인력 먼저 넣기」** — 한 번 누르면 건물마다 그날 신청한 1순위 → 2순위 → 3순위 고정 인력부터 그 건물 방에 들어간다
  (이미 배정된 방은 건드리지 않음). 나머지는 제안으로 채운다. 옆에 「배정 설정」 바로 가기.

### 4-2-a. 신청자 목록 — 누가 어디, 누가 배정 전 (가장 중요한 편의)

하루 신청자가 수십 명이라 **「이 사람 배정됐나?」를 눈으로 대조하는 일**이 지금 가장 큰 시간 낭비다. 하루 보기 오른쪽 신청자 목록이 그 답을 바로 준다.

- 맨 위 한 줄: **신청 32 · 배정 27 · 배정 전 5** · 미배정 방 3.
- 사람마다 한 줄: 이름 · 견습/우선 표시 · **상태** — 「배정 전」(신청했지만 방이 없음, 눈에 띄게 — 2026-10-20 「아직」에서 이름 바꿈. 「미배정」은 방 쪽 말) 또는 「배정 2 · 101 · 203(3명)」처럼 방 번호까지.
  기본 정렬은 **「배정 전」이 위**. 「배정 전만 보기」 한 번에 거르기.
- 방 쪽도 같은 정보를 반대로: 방마다 **들어간 사람 이름들 + 인원**(「3명」), 아무도 없는 방은 「미배정」.
  방마다 **「보통 인원」**(기본 1명, 큰 방은 **2명** — Q20)을 객실 설정에 두고, 그보다 적으면 「1명 더 필요」 한 줄.
  자동 제안도 이 인원만큼 채운다. 어느 방이 큰 방인지는 관리자가 객실마다 한 번 정한다.
- 사람을 누르면 그 사람 방이, 방을 누르면 그 방 사람들이 같이 강조된다 — 대조를 화면이 대신한다.
- **신청 안 한 사람도 본다**(사용자 지시 2026-10-20 — 급하면 연락해서 누가 신청 안 했는지 바로 봐야 한다). 거르기 세 칸:
  **신청 32 / 배정 전 5 / 신청 안 함 24**. 「신청 안 함」은 그날 신청하지 않은 현장 인원을 **최근 출근이 가까운 순**으로 —
  이름 · 알바/직원 · 우선 표시 · 「최근 출근 10/19 · 이번 달 11일」 · **전화번호(누르면 전화)** · 「대신 넣기」.
  대신 넣으면 신청자 목록으로 옮겨 가고 「관리자가 넣음」이 남는다(4-2-c).

### 4-2-b. 출근 시각

- 사람마다 **기본 출근 시각** — 처음 값은 역할로(알바 9:45 · 직원 9:00 — 알바 = 아르바이트 · 아르바이트 리더, `isHourlyRole` 2026-10-21), 특정 인원은 사람 설정에서 바꾼다.
- 그날만 다르면 배정 화면에서 그 사람 그날 시각만 고친다(예외 표시). 알바 화면 「오늘 내 방」 · 「내 시프트」에 그 시각이 보인다.
  서버(`setDayStartTime`)는 시각을 넣을 때 다른 넣기 액션과 같이 현장 멤버인지 보고(`isFieldMember`), 시각 지우기는 멤버 확인 없이(비활성 · 빠진 사람도) 있는 신청 줄만 고친다 — 신청 줄을 새로 만들지 않는다(2026-11-09, 문서 45 A17).

### 4-2-c. 대신 넣기

- 신청 안 한 사람도 관리자가 그날 넣을 수 있다(급한 건 · 앱 쓰기 어려운 사람). 넣으면 그 사람 신청 + 배정이 같이 생기고 「관리자가 넣음」이 남는다.
- 월 보기에서 그 사람 칸을 눌러 신청만 대신 넣는 것도 된다.

### 4-2-d. 당일 취소 · 변경

- 배정된 방의 예약이 취소되면 그 방은 **「취소됨」으로 남고**(조용히 사라지지 않음), 들어가 있던 사람들이 「방 없음」 상태로 위에 뜬다.
  이런 **유령 배정**(그날 청소할 방 목록에 없는 배정)은 판단 하나(`isGhostAssignment` · `liveAssignments`, 문서 45 C14)로 모든 셈에서 뺀다 —
  신청자 줄의 방 · 「배정 / 배정 전」 수(그 방만 있던 사람은 「배정 전」으로 위에), 월 보기 칸, 월 제안의 근무 일수, 비교표 배정 방 · 날, 사람 달력, 내 시프트 · 오늘 내 방 상태 · 「취소된 날」 표시 · 내일 방 수, 하루 보기 이번 달 근무 일수(월 제안과 같은 기준 — 「근무 일수 적은 사람」 비교가 일어날 때만 읽음), 하루 몫 · 오늘 건물(보드 · 제안 같은 `personDayWork`)(2026-11-09 — 예전엔 정상 배정으로 셌다).
  오늘 내 방의 흐린 「예약 바뀜」 줄은 그대로 보인다.
- **취소 요청 받아 주기는 요청이 살아 있을 때만**(2026-11-09, 문서 45 A15) — 그 사이 알바가 거뒀거나 이미 취소된 날이면 아무것도 바꾸지 않고
  「취소 요청이 이미 거둬졌거나 처리됐어요」(`errRequestGone`, ko · ja · en). 확인은 쓰기 조건으로 한다(요청이 살아 있는 줄만 바꾸고, 바뀐 줄이 없으면 배정도 지우지 않음 — 확인 뒤 쓰기 전 경쟁도 막힘). 수락은 멤버 확인 없이(비활성이 된 알바 요청도 받음, 새 줄은 안 만듦), 대신 취소는 멤버 확인. 예전엔 거둔 요청도 받아져 그날 일정이 취소됐다.
- 관리자는 사람마다 둘 중 하나: **다른 방에 붙이기**(이미 출근 — 돕기) / **그날 일정 취소**(출근 전). 연락은 지금처럼 관리자가 직접. 예약 취소된 방에서 기록 있는 사람은 빠지지 않고 교체 창에서도 잠긴다(문서 45 A6). 일정 취소(취소 요청 수락 포함)는 그 사람이 청소 중이면 막고, 끝낸 방의 배정은 남기고 시작 안 한 방만 뺀다(A7 · `planCancelDay`).
- 알림은 「막바지 일괄」 때 붙인다 — 그 사람에게 「오늘 방이 바뀌었어요 / 오늘 일정이 취소됐어요」, 배정 담당에게 「배정된 방이 취소됐어요」.
- **취소한 날은 「다시 넣기」로만 풀린다(2026-11-02 점검 수정 A4).** 예전엔 방 넣기 뒤 `ensureApplication` 이 취소를 조용히 풀어서, 모바일 청소 현황판
  「담당 넣기」 시트(접힌 「오늘 신청 안 한 사람」 안)에서 그 사람을 고르면 관리자가 취소한 날이 되살아났다. 이제:
  - 서버: `cancelledUserIds()`(`src/actions/cleaning-assign-guards.ts`)로 먼저 보고 막는다 — 방 넣기(`assignToRoom`) · 옮기기(`reassignRooms`) · 그날 출근 시각
    넣기(`setDayStartTime`, 지우기는 허용) · 방 수기 추가에 함께 넣을 사람(한 명이라도 취소면 아무것도 쓰지 않음)은 `cancelled` 실패.
    월 보기 칸 · 사람 패널의 대신 신청 토글(`toggleApplicationForUser`)도 취소된 줄은 지우지 않고 `cancelled`(지우면 다음 누름에 새 신청이 생겨 취소가 풀렸다).
    제안(하루 · 월)은 원래 취소된 사람을 뺀다.
    `ensureApplication` 은 `revive: true` 일 때만 취소를 푼다 — 「다시 넣기」(`addApplicantForDay`) 한 곳.
  - 모바일 현황판: 취소된 사람 줄은 흐리게 · 누를 수 없음 · 「일정 취소됨」(이미 그 방에 있으면 빼기만 된다). 실패 토스트 `boardDayCancelled`.
  - 오늘 내 방 빈 화면: 「배정 없음」 중 **관리자가 취소한 날**은 「관리자가 오늘 일정을 취소했어요. 나오지 않아도 돼요.」(`emptyBodyCancelled`) —
    예전엔 취소한 날도 「신청하신 날이지만 그날 방이 모두 배정됐어요」로 나와 이유가 틀렸다(`loadTodayRooms` 가 `cancelled` 를 같이 돌려준다).
  - PC 하루 보기: 원래 취소된 사람은 고를 수 없음. 서버가 `cancelled` 를 주면 토스트 `errDayCancelled`(하루 보기 · 월 보기 · 사람 패널 · 모바일 사람 시프트). 문구 모두 ko · ja · en.
  - **DB 도 막는다(점검 C1, 마이그레이션 202611020010)** — 취소된 날 배정 넣기는 트리거 `cleaning_assignments_cancelled_day` 가 거절한다
    (앱 확인을 빠져나간 경우의 마지막 방어선). 「다시 넣기」는 취소를 먼저 풀어서 걸리지 않는다.
  - **미루기 · 처리 끝 되돌리기(`releaseHold`)도 취소된 사람은 다시 넣지 않는다**(2026-11-02 리뷰) — 미룰 때 뺀 사람 중 그 사이 그날 일정을 취소한 사람은 빼고 넣는다.
    다시 넣을 사람(현장 직원인지 · 취소했는지)은 **미룸 기록을 지우기 전에** 정하고, 취소 여부를 못 읽으면 지우지 않고 오류를 돌려준다
    (지운 뒤에 실패하면 `removed_user_ids` 가 사라져 뺀 사람을 되찾을 수 없었다). 배정을 넣는 모든 길: 방 넣기 · 옮기기 · 방 수기 추가 · 되돌리기는 취소 확인, 제안(하루 · 월)은 원래 취소된 사람 제외.
  - **월 보기 칸**: 취소된 날은 빈칸이 아니라 짧은 회색 줄(`cas-cellx`, 읽기 이름 「일정 취소됨」 `monthCancelledCell`). 누르면 서버를 부르지 않고
    「이날 일정이 취소된 사람이에요. 하루 보기의 「다시 넣기」로 살릴 수 있어요」(`monthCancelledHint`). 범례에도 「일정 취소됨」 줄을 넣고,
    지난 날 칸(눌리지 않음)은 마우스를 올리면 같은 이름이 뜬다(`title`).
  - **모바일 현황판 여러 명 저장**: 한 사람씩 보내다 중간에 실패하면 이유 뒤에 「앞의 변경은 저장됐어요」(`boardPartlySaved`)를 붙이고 새로 읽는다.

### 4-2-e. 한 방 여러 명 · 신입 견습

- 한 방에 **여러 명**(2~3명)을 넣을 수 있다. 막는 것은 **같은 사람을 같은 방에 두 번**뿐이다.
- **여러 명 방은 각자 기록(2026-11-02 사용자 결정 ① · 점검 C1, 마이그레이션 202611020010):** 배정된 사람마다 오늘 내 방에서 따로 시작 ·
  끝내고 청소 기록도 사람마다 하나씩 남는다(급여 · 교통비 · 현장 활동 · 비교표가 사람마다 센다). 누가 시작할 수
  있나: 그날 그 방에 배정된 사람은 자기 기록이 없으면 언제나(남이 먼저 해도 배정된 자리는 빼앗기지 않는다). 배정 안 된 사람(배정 없는
  방 포함)은 그 방에 아직 아무 기록이 없을 때만 — 배정 없는 방은 예전처럼 한 사람. 「처리 끝」 방은 아무도. 한 사람은 그날 한 방에 기록 하나.
  - 오늘 내 방: 같이 하는 사람이 먼저 시작 · 끝내도 내 줄은 「대기 · 시작」 그대로. 「같이」 칸에 「이름 · 청소 중」 / 「이름 · 끝남」
    (`mateStateProgress` · `mateStateDone`). 내 기록이 생기면 그 상태로 보인다.
  - 방 상태(PC 하루 보기 · 모바일 현황판 · PC 청소 현황 카드)는 방 기준 하나(`roomShareState`): 한 사람이라도 청소 중이면 「청소 중」,
    끝낸 사람 수가 그날 그 방 배정 인원(없으면 1)에 닿으면 「끝남」, 일부만 끝냈으면 **「1/2 끝남」**(2026-11-02 사용자 결정 —
    `statusPartial` · `stPartial`). 「1/2 끝남」 방은 아직 다 끝난 방이 아니라 「청소 중」 칸 · 수로 세고, 흐른 분은 그리지 않는다
    (현황판 원은 끝낸 몫만큼 채움). 배정 안 된 사람이 끝낸 것도 센다(그 방을 치웠다). 현황판 「끝남」 시각은 마지막 사람이 끝낸 시각.
    콘솔 카드의 기록 상태(`task.status`)는 그대로라 상세는 그 기록을 쓰고, 「같이 한 사람 완료 처리」는 **「1/2 끝남」일 때만** 뜬다
    (끝난 방에 빠진 사람을 내밀지 않게). 「1/2 끝남」 카드에는 분을 그리지 않는다. PC 직원별 요약은 카드가 아니라 사람마다 기록으로 센다
    (`task.workers` — 2인 방 두 번째 사람 몫도 들어간다).
  - PC 청소 현황 카드 담당 칸에 기록 있는 사람을 모두 「A · B」로. 방이 「끝남」이어도 아직 기록이 없는 배정 직원이 있으면 상세 패널에
    「같이 한 사람 완료 처리」(`forceDoneMissing`) — 그 사람을 담당으로 새 완료 기록(서버가 같은 규칙 · 중복을 다시 본다).
  - 같은 순간 둘이 눌러도 DB 가 막는다(방 트리거 · 한 사람 한 방 유니크 — 문서 04 `cleaning_sessions`).
  - 화면이 「시작」을 내미는 규칙도 하나(`shouldOfferStart` — 오늘 내 방 · 청소 화면 `/mobile/cleaning` 같음): 서버가 받아 주고, 그 방
    다른 기록이 **모두 같이 배정된 사람 것**일 때만. 배정 안 된 사람이 해 둔 방 · 「처리 끝」 방은 그 기록으로 보이거나(오늘 내 방) 숨는다
    (청소 화면) — 이미 치운 방을 다시 청소하지 않게. 서버는 배정된 사람을 막지 않는다(배정된 자리는 그 사람 몫).
- **보통 인원보다 많이 넣을 때 확인(2026-10-23 사용자 지시 — 관리자 실수 방지, 시안 https://claude.ai/artifact/P297A6EKX5ofrx8dEFn8t1):**
  방에 이미 보통 인원(객실 설정 「큰 방」, 기본 1명)만큼 들어가 있는데 한 명 더 넣으려 하면 가운데 확인 창 —
  「신주쿠5 401 방은 보통 2명이에요 · 이미 ○○ · △△ 2명이 들어가 있어요. □□ 님까지 넣으면 3명이 돼요」 · 얼굴(새 사람은 보라) · 「3명 / 보통 2명」 ·
  [그대로 두기] [3명으로 넣기](처음 포커스 — Enter 넣기 · Esc · 바깥 누르면 그대로). 넣는 사람이나 방 안 사람이 견습이면
  「견습을 같이 붙이는 거라면 그대로 넣으세요」 한 줄. 막지는 않는다. 넣은 뒤 방 줄에 주황 「3/2 · 1명 많음」.
  걸리는 곳: 하루 보기의 넣기(사람 고른 상태의 방 줄 · 「+ 사람」 창). 제안 · 「+ 사람」은 원래 빈 자리에만 나온다.
- 사람 칸에 **「견습」 표시**(신입). 견습은 혼자 두지 않는다 — 자동 제안은 견습을 **현장 매니저 · 견습 담당이 있는 방에만** 붙이고,
  관리자가 견습 혼자 방에 넣으면 경고 한 줄(막지는 않음).
- 견습 사람 옆에 **「견습 N번째」**(전 건물 통합으로 센다) — 눌러 보면 **건물별 몇 번**(아라키초A 2 · 가부키초 1 …). 어느 건물이 처음인지
  바로 보여서 같은 건물만 돌지 않게 고를 수 있다.
- 견습 떼기는 **관리자가** 한다(Q18). 평균 4~5회지만 사람마다 다르므로 자동으로 떼지 않는다.
  대신 **견습 횟수가 많아지면**(6회째부터, Q21 확정) 그 사람 줄과 배정 화면에 「아직 견습인가요?」 확인이 뜬다 —
  「견습 끝」 또는 「계속 견습」(그 뒤 2회 더 지나면 다시 묻기). 잊고 계속 견습으로 남는 것을 막는다.

### 4-2-f. 여러 명이 동시에 고칠 때 (건물마다 담당 2명 정도)

- **방 하나씩 저장한다** — 하루 전체를 한 번에 덮어쓰는 「저장」 버튼이 없다. 방을 사람에게 놓는 순간 그 한 건만 서버에 간다.
  그래서 A 가 101호를, B 가 102호를 동시에 고쳐도 서로 지우지 않는다.
- **같은 사람을 같은 방에 두 번 넣을 수 없다** — DB 유일 제약(날짜 × 방 × 사람)으로 막는다. 화면이 아니라 서버가 막으므로 두 사람이 동시에 눌러도 하나만 들어간다.
- 한 방에 여러 명이 들어가므로 「옮기기」는 **빼기 + 넣기** 두 건이다. 이미 빠진 사람을 또 빼거나, 이미 들어간 사람을 또 넣으면
  늦게 도착한 쪽은 「방금 ○○님이 바꿨어요」로 돌려받고 화면이 새 값으로 바뀐다(조용히 덮어쓰지 않음).
- 보드는 실시간으로 갱신된다 — 다른 담당자가 넣은 배정이 바로 보이고, 줄에 「누가 · 언제」가 남는다.
- **실시간(2026-10-22 사용자 지시 — 「모바일에서 신청하고 대시보드에서 새로고침하는 번거로움」):** 신청 · 신청 취소 · 취소 요청(모바일)과
  배정 · 빼기 · 바꾸기 · 미루기 · 처리 끝 · 대신 넣기 · 출근 시각 · 제안 넣기(PC)가 저장되면 서버가 조직 채널로 「바뀌었다」 신호
  (`signalCleaningAssignChange`, 종류 `cleaning_assign`)를 보내고, 열려 있는 배정 화면(하루 · 월)과 내 시프트 · 오늘 내 방이 새로고침 없이
  다시 읽는다(약 2초). 신호에는 데이터가 없고 화면은 평소 권한 검사로 다시 읽는다. 배정 설정(담당마다 따로)은 신호를 보내지 않는다.
  하루 보기의 20초 새로 불러오기는 청소 진행(청소 중 · 끝남) 표시용으로 그대로 둔다.
- 월말 자동 제안 반영도 **미배정 방만** 채우므로 다른 담당자가 먼저 넣은 배정을 덮지 않는다.

### 4-5. 배정 설정 — PC (관리자, 2026-10-20 사용자 제안)

제안 기준을 고정하지 않고 **관리자가 직접 정한다.** 다만 규칙을 자유롭게 만드는 방식은 쓰기 어렵고 실수가 나기 쉬우므로,
**정해진 항목을 켜고 끄고 순서만 바꾼다.** 세 칸.

- **동료 보기는 내가 배정된 날 중 오늘 · 내일만**(Q8-b 확정): 그날 같이 일하는 사람 이름과 그 사람 방. 함께 들어가는 방은 같이 들어가는 사람 표시.
- 내가 배정되지 않은 날, 다른 날짜의 배정, 다른 사람이 몇 개를 받았는지 · 누가 신청했다가 못 받았는지는 **보이지 않는다**(불만 · 논쟁 방지).

- 앱을 열면 배정된 방만 순서대로. 누르면 지금의 청소 시작(타이머)으로 이어진다.
- 배정이 바뀌면 목록이 바로 바뀐다. 전날 밤(예: 11시)에 바뀐 것은 아침에 **「어젯밤 바뀜」** 표시로 알아채게 한다(Q13-b).
  알림은 「막바지 일괄」 규칙 — 지금은 붙이지 않는다.

- **2026-10-28 — 이 화면에서 바로 청소한다.** 「청소 시작」을 누르면 다른 화면으로 가지 않고 그 자리에서 타이머 → 「청소 끝내기」(남색) → 「되돌리기」 토스트(2분 안).
  동료가 청소 중인 방은 「○○ 님이 청소 중」. 목록 아래 「목록에 없는 방 · 셋팅 청소」(→ `/mobile/cleaning?work=1`). 배정 담당은 `/mobile/cleaning` 청소 현황판에서
  방마다 상태를 보고 담당을 넣는다. 자세한 것: `07-cleaning-workflow.md` 「2026-10-28 모바일 청소 현황판」. 「보통 N분」은 나중(방마다 기록 5건 넘으면 중앙값 자동).

### 4-4. 예정 vs 실제 · 급여 비교 — PC (나중)

- **월 비교표**: 사람마다 한 줄 — 배정 방 수 · 실제 청소한 방 수(청소 기록) · 출근 시간 · 그달 급여 · **방당 급여 · 방당 시간**.
  다른 사람들보다 크게 벗어난 줄을 표시한다(방은 많은데 급여가 적다 / 방은 적은데 급여가 높다). 청소만의 문제가 아닐 수 있지만 의심할 신호.
  급여는 지금의 근태 · 급여(`docs/product/21-attendance-payroll-workflow.md`) 값을 그대로 읽는다 — 급여 계산은 바꾸지 않는다.
  **청소 수는 자기 기록이 있는 방만 1개로 센다**(나누지 않음, 2026-11-04 Q19 변경 · 문서 45 C5).
- 화면(시안 ⑥): 달 고르기 · 건물 · 「견습 · 직원 빼고 비교」(기본 켜짐 — 견습은 혼자 맡는 방이 적어 방당 값이 튀고, 직원은 청소 말고 일이 많다) ·
  Excel · PDF(공용 내보내기, §4b). 위 숫자 셋 — **평균 방당 급여 · 평균 방당 시간 · 평균에서 25% 넘게 벗어난 사람 수** → 그 아래
  **「확인할 사람」 줄**(벗어난 사람마다 방 수 · 급여 · 방당 급여(±%) · 방당 시간 · 「출근 기록 보기」) → 읽는 법 작은 글씨 한 줄.
  **많아도 3줄까지**(평균에서 많이 벗어난 순) + 「N명 더 · 표에서 신호 있는 사람만 보기」 — 누르면 아래 표가 신호 있는 사람만으로 걸러진다.
  윗부분 높이가 늘 같아서 그래프 옆 배치가 흔들리지 않는다. 0명이면 「이번 달은 평균에서 크게 벗어난 사람이 없어요」 한 줄.
  벗어남 **기준은 고를 수 있다**(숫자 이름표의 「25% ⌄」 — 10% · 25% …, 기본 25%). 시안 「확인할 사람이 많을 때」 = 기준 10%, 4명 중 3명 + 「1명 더」. 오른쪽 점 그래프(가로 청소한 방 · 세로 급여 · 평균 방당 급여 선) — 선에서 먼 점에 이름.
  표: 이름 · 근무일 · 배정 방 · 청소한 방 · 근무 시간 · 급여 · **방당 급여(정렬 기본)** · 방당 시간 · 신호(+25% 넘음 빨강 「확인」 / −25% 넘음 주황).
  금액은 엔 단위 정확 표기(¥57,960).

- 배정된 날 ↔ 실제 출근, 배정 방 ↔ 실제 청소 기록. 미시작 방 · 미출근을 한눈에.

- 신청 가능 범위: 오늘 ~ 92일 뒤. 관리자 배정 가능 범위: 어제(기록 정리) ~ 120일 뒤.
- 태블릿 오른쪽 칸과 본문 사이 세로줄 없음(리디자인 규칙) — 여백으로만 나눈다.
- **큰 읽기는 `readAllPages`** — Supabase 는 한 번에 1,000줄까지만 준다(`limit(10000)` 도 1,000에서 잘림, 2026-10-21 확인). 배정(한 달 방 수십 × 2~3명) ·
  견습 횟수(전 기간) · 최근 출근(90일) · 월 퇴실 · 비교표 청소 기록 · 미룸 기간 청소 기록은 페이지로 끝까지 읽는다.
- **미루기 · 처리 끝은 하루 · 월 모두 같은 계산**(`buildDayRooms` · `countOpenRooms`, `src/lib/cleaning-assign/room-rules.ts`) — 월 보기 미배정 수와 월 자동 제안도 끝난 방 · 미룬 방 · 처리 끝 방을 뺀다(문서 45 C9).
- **되돌리기는 그 동작을 한 날짜로(2026-11-09, 문서 45 A14):** 빼기 · 담당 바꾸기 · 미루기 · 처리 끝의 5초 되돌리기는 동작한 날짜를 같이 기억해 그 날로 보낸다
  (토스트가 떠 있는 사이 다른 날로 옮겨도 원래 날을 고친다 — 예전엔 지금 보는 날로 보내 엉뚱한 날을 고쳤다).
- **미루기 · 처리 끝 되돌리기(2026-10-21 사용자 지시 — 실수로 누른 경우):** 누르면 아래에 5초 **「실행 취소」 토스트**(공용 `AdminUndoToast`) —
  누르면 미룸 · 처리 끝이 풀리고 **그때 뺀 배정도 다시 넣는다**. 토스트가 지난 뒤에도 그날 방 줄에 「N일로 미룸」 · **「처리 끝」**(청소 끝남과 구분)
  표시 + 「되돌리기」가 남고, **이것도 뺀 사람까지 다시 넣는다** — 뺀 사람은 미룸 줄 `cleaning_room_holds.removed_user_ids` 에 남는다
  (마이그레이션 202610210003, 다시 미루면 합침). 토스트와 줄 버튼이 같은 `releaseHold`.
  밀려 온 방(어제 이전 것)을 미루거나 처리 끝으로 둔 경우도 **그렇게 한 날에는** 목록에 남겨 되돌릴 수 있다(다음 날부터는 지금처럼 안 보임).
  **밀려 온 방이 오늘 체크아웃도 있을 때(2026-11-02 데모에서 발견)**: 미룸 · 처리 끝 기록은 처음 날(C) 하나로 남는데, 예전엔 오늘 방 줄이 그 기록을 못 봐서
  미뤄도 줄이 그대로 「미배정」(처리 끝은 「끝남」만, 되돌리기 없음)으로 보였고 오늘 내 방 화면도 막지 않았다. 이제 같은 방의 미룸 · 처리 끝 중
  「C ≤ 그날 ≤ 그렇게 한 날」이고 아직 기간 안인 것을 그날 것으로도 본다(`loadAssignDayRooms` `holdFor`) — 오늘 줄에 「N일로 미룸 · 되돌리기」 /
  「처리 끝 · 되돌리기」가 뜨고(되돌리기는 C 날짜로), 다음 날 오늘 체크아웃 몫이 「밀려 온 방」으로 다시 뜨지도 않는다. 미룬 뒤에 생긴 체크아웃은 덮지 않는다.
  미룬 · 처리 끝 방에는 배정을 넣을 수 없다(서버도 막음).
- **처리 끝 = 청소 기록(2026-10-21 사용자 지시):** 처리 끝은 PC 청소 대시보드 강제완료처럼 그날 청소 완료 기록을 남긴다 — 표시
  `cleaning_sessions.closed_without_cleaning`, 담당자 = 누른 관리자, 청소 현황 · 기록에는 **「처리 끝 · 청소 안 함」**. 사람별 숫자에서는 빠지고,
  되돌리면 기록도 지운다(미룸 줄 `closed_session_id`, 마이그레이션 202610210005). 상세 docs/product/07-cleaning-workflow.md 「강제완료」.
- 「날짜 정해 미루기」는 최대 60일(`MAX_DEFER_DAYS`) — 방 목록이 그만큼(+ 밀린 7일) 앞의 미룸까지 찾아, 정한 날 청소 기록이 없으면 다시 띄운다.
  배정이 하나도 없던 날 미룬 방도 다음 날 다시 뜬다.
- 하루 보기에서 그날 일정을 취소한 사람은 줄에 **「다시 넣기」**(취소 되돌리기). 신청자 줄은 이름 칸만 고르기 버튼(줄 안에 다른 버튼이 있어 줄 전체를 버튼으로 두지 않는다).
- 화면에 찍는 시각은 `tokyoTime()`(숫자만, 도쿄) — `toLocaleString` 은 서버와 브라우저가 「오전」/「AM」으로 갈려 하이드레이션이 어긋났다.
- 알바가 약 3달(92일) 넘는 날을 누르면 「약 3달 뒤까지만」 안내(전에는 「지난날」로 잘못 나옴). 월 제안의 「근무 일수 적은 사람 먼저」는 방 수가 아니라 날 수로, 앞날 제안도 더해 센다.
