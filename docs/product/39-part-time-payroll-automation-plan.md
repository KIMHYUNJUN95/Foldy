## 0. 원칙

1. **엑셀의 모든 시트 · 열 · 칸이 Foldy 에 대응한다**(§2 표에 빠짐없이). 「안 함」은 이유와 함께 적는다.
2. 사람이 하던 일은 **자동 · 기본값**으로, 남는 손 입력은 **한 화면 한 표**에서 끝낸다(엑셀 입력 시트와 같은 열 순서).
3. 숫자는 **엑셀과 1엔도 다르지 않게**(같은 반올림 · 올림). 9월분 실제 엑셀 값으로 맞춰 보는 테스트(§10).
4. 출력은 **엑셀 + PDF**(관리자 콘솔 규칙 4b). 엑셀은 원본과 **같은 시트 이름 · 순서 · 칸 배치(일본어 고정 양식)** — 지금 받아 보는 사람(사장 · 専務 · 세무 · 알바)이 그대로 쓸 수 있게.
   단 **수당 칸 이름은 인사팀 답변(§1-A)대로 바꾼다**(残業手当 · 週末手当 · 特別手当 · 前月調整額).
5. 화면 문구는 ko · ja · en. 돈 · 개인정보는 권한 키로만(§8).

## 3. 새로 받는 데이터

### 3-A. 사람별 급여 설정 (시급 화면 옆, 이력 없이 「지금 값」 + 변경 기록)
- **지급 방식**: 현금 / 계좌이체 — **본인 희망**. 기본값 없음, 안 고르면 급여 준비에서 「확인 필요」.
- **원천세 구분**: 甲 / 乙 / 丙 — 거주자만. 워킹홀리데이 = 甲, 2개월 이내 고용 = 丙. 안 고르면 「확인 필요」.
  (2개월 이내 고용으로 들어온 사람이 계속 일하게 되면 구분을 바꾸라는 안내 — 입사일 기준 2개월 지나면 「확인 필요」)
- **부양 인원**(甲일 때 0~7, 기본 0) — §11-5
- **일본 이름(氏名) = 가타카나** — 명세서 · 사장표 · 세무사용 명세(세무사에겐 가타카나로 보냄)
- **雇用保険 가입 여부 · 가입일**(내년부터) — 가입자만 U열 계산
- **급여 계좌**(2026-10-26 추가) — 은행 · 지점 · 종류(보통 / 당좌) · 번호(7자리) · 명의(가타카나). 본인이 내 계정에서, 관리자가 대신 고친다.
  본인이 바꾸면 급여 담당 확인 전까지 이체는 이전에 확인한 계좌로. 보기는 본인 + `payroll.view`. → 아래 「지급 방식 · 지난달 값 · 급여 계좌 구현」

### 3-B. 달마다 사람별 손 입력 (급여 준비 화면 한 표)
- 지급: 残業手当 · 週末手当 · 特別手当(Foldy 추가수당이 먼저 채워지고 더하거나 고침) · **前月調整額(±, 몇 월분 필수)** · 通勤課税(규칙 밖일 때)
- 공제: 雇用保険(가입자 · 자동값 덮어쓰기) · 年末調整(±) · 源泉所得税 덮어쓰기(사유). 健康 · 介護 · 厚生年金 · 住民税는 없음(0)
- 근태 보충: 欠勤日数 · 残業時間 · 週末出勤日数 · 週末出勤時間(자동 아닌 것만)
- 支払方法 그 달만 바꾸기(2026-10-26 구현 — `payment_method_override`) · 備考
- 저장 = 그 달 「급여 준비 값」(마감 전까지 고침, 마감 때 스냅샷에 같이 굳힘)

### 3-C. 회사 설정
- 会社名(명세서 표기), 지급일 규칙(매월 10일 · **휴일이면 앞당김** — 일본 공휴일 달력), 결재자(専務 · 社長), 雇用保険 근로자 부담률(연도별)

### 3-D. 세금표
- 연도별 `源泉徴収税額表` — 月額表(甲 0~7명 · 乙) + 日額表 丙 · 구간(이상 · 미만). 국세청 표 그대로 넣고, **새해 표가 없으면 마감을 막고 알림**.

## 4. 계산 규칙 (엑셀과 1엔 일치)

### 4-A. 순서
```
시급 구간별 시간 h_k(분 합계 → 시각값) , 支給額_k = ROUND(시급_k × h_k)      ← 엑셀과 같게: 구간별 월 합계 시간에 곱하고 엔 반올림
課税計 P   = Σ支給額_k + 前月調整額 + 残業手当 + 週末手当 + 特別手当 + 通勤課税
支給額合計 Q = P + 通勤非課税
社会保険計 V = 雇用保険(가입자만, 나머지 0)
源泉税 W   = §4-B
控除合計 Z = V + W + 年末調整            (住民税 = 0)
差引 AB    = Q − Z                    ← 1엔 단위 그대로 지급(2026-10-27 사용자 결정 — 10엔 올림 폐지)
支給額_k   = ROUNDUP(시급 × 분 ÷ 60)  ← 시급 × 분 금액에 소수점이 생기면 1엔 올림(같은 결정 — 반올림 ROUND 대신). 자동 수당(잔업 · 주말 · 특별)도 같음
```
- 雇用保険 = 그 달 賃金総額(通勤 포함) × 근로자 부담률, 1엔 미만 끝처리는 법정 규칙(50전 이하 버림 · 초과 올림) — §11-13.
- 前月調整額은 課税計에 들어간다(조정 대상이 과세 급여라는 전제 — 비과세 교통비 조정이면 通勤非課税로 넣기, §11-14).
- **시간은 1분 단위**(사용자 2026-10-22 「지금 1분 단위로 처리」): 15분 · 30분 단위 끊기 없음. 근무 1건 = 출근 ~ 퇴근(휴게 뺌)을 분으로(초는 버림),
  시급 구간별로 그 달 분을 다 더한 뒤 `ROUND(시급 × 분 ÷ 60)` — 엑셀 `ROUND(시급 × 시간 × 24)` 와 같은 값.
- **지금 Foldy 와 다른 점**: (1) 근무 1건마다 금액을 내고 더함 → 구간별 월 합계 분에 시급을 한 번 곱함, (2) 총액 10엔 올림 → 구간 금액 1엔 올림 · 실수령 1엔 단위(2026-10-27).
  기존 「근태 급여 화면 · 내보내기」 숫자도 같이 바뀐다 — 마감된 달은 그대로, 새 규칙은 적용 시작 달부터(§11-10).

### 4-B. 원천세
> **최신 국세청 표 기준으로 정해짐(인사팀 답변 2026-10-26).** 옛 엑셀 규칙(乙 9,300엔 하한 · 보험료 빼기 전 조회 · 甲 0명 고정 · 丙 0)은 쓰지 않는다.
- 조회 금액 = 課税計 − 사회보험(雇用保険) — 국세청 표 「社会保険料等控除後の給与等の金額」.
- 丙(2개월 이내 고용) → **근무한 날마다** 日額表 丙 열로 계산해 한 달 합계(令和8年 하루 9,800엔 · 令和9年 10,000엔 미만인 날은 0).
  출력 엑셀에 日額表 丙 시트도 같이 넣는다.
- 乙 → 표 乙 열 — 令和8年 105,000엔 미만은 하한 없이 `ROUNDDOWN(x × 3.063%)`(令和9年은 111,000엔 미만).
  엑셀의 「9,300 미만 = 0」은 옛 丙 하루 기준이 잘못 옮겨진 것 — 쓰지 않는다(§11-12).
- 甲(워킹홀리데이 포함) → 표의 사람별 부양 인원 열(§11-5).
- 표 조회: 구간 `이상 ≤ x < 미만`, **표 전 구간**(엑셀처럼 50만엔에서 끊기지 않음). 표 범위를 넘는 고액은 국세청 산식 — §11-5.
- 甲乙丙은 거주자만 — 지금 비거주자 알바 없음, 워킹홀리데이는 사장 지시로 甲(扶養控除等申告書 받음) — 인사팀 2026-10-26(§11-15).
- 甲 부양 인원은 지금 전원 0명 — 생기면 인사팀이 이름 · 인원을 알려 주고 급여 설정에 넣는다.
- 적용 시작: **10월분(11/10 지급)부터** 국세청 방식(세무사 2026-10-26). 丙은 2개월 이내 단기만이고 하루 급여를 과세 기준 미만으로 해서 보통 0엔 — 그래도 표대로 계산.

## 5. 화면 (관리자 웹 — 근태 › 급여 아래, PC · 폰 · 폴드 · 태블릿)

- **A. 급여 준비 (달별 표)**: 엑셀 입력 시트와 같은 열 순서의 표 하나 — 자동 칸은 회색 잠금, 손 칸만 입력. 위쪽 탭 「현금 n명 · 이체 m명」.
  합계 줄 · 「지난달 값 이어 쓰기」 · 저장 상태 · 오류(세금표 없음 · 일본 이름 없음 · 甲乙丙 없음 · 지급 방식 없음 · 前月調整額에 몇 월분 없음) 표시.
  0 고정 칸(健康 · 介護 · 厚生年金 · 住民税)은 표에서 접어 둠.
- **B. 사람별 급여 설정**: 시급 화면에 지급 방식 · 甲乙丙 · 부양 · 일본 이름 · 雇用保険 가입 칸.
- **C. 결재**: 「사장 확인표」 화면 — 이체 / 현금 목록 · 합계 · 総合計 → 専務 결재 → 社長 결재(순서 · 되돌리기). 결재 뒤 값 바꾸면 결재 풀림.
- **D. 확인 필요**: 정정 요청 미처리 · 손 수정 · 마감 후 변경 · 시간 0 인 사람 · 설정 빠진 사람 · 丙 2개월 넘김 — 지금 근태 마감 차단과 합침.
- **E. 지급 확인**: 사람별 「봉투 넣음 · 본인 확인(현금) / 이체 완료(이체)」 체크(누가 · 언제), 다 되면 그 달 「지급 완료」.
- **F. 출력**: 「급여 엑셀(전체 시트)」 · 「명세서 PDF(현금 / 이체)」 · 「사장 확인표 PDF」 · 「지급 확인 목록 PDF」 · **「세무사용 甲欄 / 丙欄 명세」**.
- (뒤 단계) 알바 본인 앱에서 내 명세서 보기 — §11-11.

## 6. 출력 파일 규격

- 엑셀: 원본과 같은 10시트 · 같은 이름 · 순서 · 열 너비 · 병합 · 인쇄 설정(명세서 A4 세로 2명 · 28행 블록 · 행 나눔), 값 + **같은 수식**(엑셀에서 손 고쳐도 다시 계산).
  외부 파일 VLOOKUP 은 값으로 대체. 사람 수 제한 없음. 수당 칸 라벨만 §2-A 대로.
  **수식 흐름은 원본 그대로**: 입력 시트(현금 · 이체)에서 F · I · P · Q · V · W · Z · AA · AB 를 계산 → 명세서 블록 n 은 입력 시트 `n+2` 행을 참조,
  사장 확인표 · 支給確認一覧 · 勤務表チェック 도 입력 시트를 참조 → 입력 칸 하나만 고쳐도 명세서 · 합계가 같이 바뀐다.
  Foldy 화면의 계산 엔진과 엑셀 수식은 같은 규칙(§4) — 골든 테스트에서 둘 다 대조. 파일 이름 `新アルバイト給与管理YYYYMMDD.xlsx`(지급일).
- **세무사용 명세** — 지금 파일 `アルバイト給与一覧YYYYMMDD(税理士用).xlsx` 와 같은 양식(2026-10-22 구조 점검, 9월분):
  - 시트 하나, 이름 `YYYY.M月分`(예 `2026.9月分`). 글꼴 游ゴシック 11, 금액 서식 `#,##0 ;[Red](#,##0)`, 열 너비 A 21.4 · B~F 11.1.
  - 구분마다 한 덩어리: 제목 줄 `甲欄アルバイト` → 열 이름 줄 → 사람 줄 → `合計` 줄(SUM) → 빈 줄 → `乙欄アルバイト` … (丙 있으면 `丙欄アルバイト`). 사람 없는 구분은 안 그림.
  - 열(엑셀 9월판과 대조해 맞춘 출처):

    | 열 | 이름 | 값(급여 입력 시트) |
    | --- | --- | --- |
    | A | 氏名 | **세무용 이름 = 가타카나**(입력 시트 C 氏名과 같음) |
    | B | 支給額 | 지금 파일은 Q 支給額合計(교통비 포함) → **Foldy 는 課税計 P(교통비 뺀 과세 금액)** — 교통비는 전부 비과세 |
    | C | 交通費 | O 通勤非課税 |
    | D | 総支給額 | Q 支給額合計 |
    | E | 源泉所得税 | W |
    | F | 差引支給額 | 지금 파일은 수식 `D − E`(10엔 올림 없음) → **Foldy 는 실제 지급액 AB**(1엔 단위 · 공제 반영) |
    | G | 出勤日数 | AC |

  - 지금 파일은 손으로 옮겨 적은 값이라 9월분에서 **급여 엑셀과 다른 곳**이 있었다: 総支給額이 급여 엑셀과 다른 사람 1명, 급여 엑셀에 甲乙丙이 빈칸인데 甲欄에 들어간 사람 1명.
    Foldy 는 급여 입력값에서 바로 만들어 이런 차이가 안 생긴다.
  - 바꾸는 이유: 교통비는 전부 비과세라 支給額 = 課税計 + 交通費 = 総支給額 이 되어야 표가 맞고, 差引은 실제로 준 돈이어야 한다.
    (2026-10-27 이후 1엔 단위라 이 차이는 없다.) 예전엔 10엔 올림으로 생기는 1~9엔이 総支給額 − 源泉 과 差引의 차이로 남았다 — 지금도 세무사에게 올림한 금액으로 보내고 있어 그대로 둔다(§11-16, 2026-10-26 사용자 확인).
- PDF: 명세서(현금 · 이체 따로, A4 2명 · 절취선 · 検印), 사장 확인표, 지급 확인 목록, 세무사용 명세 — 엑셀과 같은 숫자.
- 결재 요청 뒤엔 **결재 요청 때 굳힌 스냅샷**에서 만든다(다시 뽑아도 같은 숫자, P5). 급여 준비 중엔 그 순간의 급여 준비 값.
- 결재 도장(専務 · 社長 칸 = 이름 · 날짜) · 지급 체크(封入確認 · 本人確認 = 「済」)를 같이 찍는다(P5).

## 7. 엑셀 오류 처리 (따라 하지 않음)
`#REF!` 칸 · 50/49칸 제한 · 줄 밀림 · 사장표 29명 · 현금 13~19행 누락 · M열 라벨 불일치 · 세금표 161행 끊김 — 모두 Foldy 에선 생기지 않게. 세금 조회 기준(사회보험 전/후)은 §11-5.

## 8. 권한 (이미 있는 키 + 하나)

### P2 구현 (2026-10-25)

- **세금표** — 국세청 `給与所得の源泉徴収税額表` 엑셀(令和8年分 · 令和9年分)을 그대로 옮긴 생성 파일 `src/lib/withholding-tax/table-2026.ts` · `table-2027.ts`

  - **어느 해 표인지 = 지급일의 해**(12월분을 1월에 주면 새해 표). 표가 없는 해는 계산하지 않고 「세금표 없음」(`no_tax_table`) — 새해 표가 나오면 생성기로 파일 추가.

  - 시급 구간마다 그 달 분 합계 × 시급 ÷ 60 을 **엑셀 ROUND**(0.5 는 위로) — 기존 `calculateMonthlyPay().rateSegments` 의 분을 그대로 넣으면 된다.

    가입자인데 율이 없으면 `no_insurance_rate`.
  - ~~**실수령 10엔 올림**~~(2026-10-27 폐지 → 아래 「1엔 단위 지급」): 差引 AB = CEILING(Q − Z, 10), 올림 끝돈(0~9엔)은 `roundUpYen` 으로 따로 낸다(세무사용 명세 · §11-16 — 지금처럼 올림한 금액 그대로).

- **원천세 규칙 스위치**(`PayrollTaxRules`). 기본값 `DEFAULT_PAYROLL_TAX_RULES` = **최신 국세청 표 기준**(인사팀 답변 2026-10-26로 바꿈).

### 1엔 단위 지급 (2026-10-27)

사용자: 「원래 10엔 단위로 지급이었는데 다시 바뀌었어. 1분 단위는 그대로고 1엔 단위로 지급, 소수점이면 1엔으로 올림」.
결정: **시급 구간 금액부터 1엔 올림**(ROUND → ROUNDUP), 실수령은 Q − Z 그대로(10엔 올림 폐지). **아직 결재 전인 달부터** — 10월분부터.

- 엔진 `src/lib/payroll-month-calc.ts`: 구간 금액 · 자동 수당(잔업 · 주말 · 특별) = `ceilYen()`(부동소수 끝은 `settleYen` 으로 먼저 맞춤), `netPay = Q − Z`, `ceilTo10` · `roundUpYen` 없앰.
  교통비는 실제 운임이라 그대로(ROUND), 雇用保険 50전 규칙도 그대로(법 규칙).
- `PrepRow.roundUpYen` 은 선택 칸 — 2026-10-27 전에 굳힌 결재 스냅샷에만 있다(운영엔 그런 스냅샷 0건, 확인함). 「올림 +n」 줄은 그때만 보인다.
- 급여 엑셀 `新アルバイト給与管理`: F · I = `ROUNDUP(ROUND(시급 × 시간 × 24, 6), 0)`(부동소수 끝을 먼저 6자리에서 맞춘 뒤 올림), AB = `Q − Z`.
- 예전 급여 검토 표 · 내 급여 화면(`attendance-pay-calculation.ts`): 월 합계 올림이 달마다 — `ONE_YEN_PAY_START_YM`(2026-10)부터 1엔, 그 전 달(지급 끝)은 10엔.
  안내 문구 「1엔 미만은 올림합니다」 / 그 전 달은 「월 합계는 10엔 단위로 올림합니다」(ko · ja · en).
- 1분 단위 근무 시간은 그대로.
- 테스트: `payroll-month-calc` · `payroll-prep` · `payroll-export` · `attendance-pay`(`ceilMonthlyPay`).

### 지급 방식 · 지난달 값 · 급여 계좌 구현 (2026-10-26)

시안: 「급여 · 지급 방식 · 계좌 시안」 캔버스(https://claude.ai/artifact/6PcLUew4m75yxZ31Qb7A1G). 사용자 요청 — 「중간중간 계좌번호를 수정하는 경우도 있어」.
결정(사용자 확정): 고치기 = 본인 + 관리자 대신 · 보기 = 본인 + `payroll.view` · 바뀐 기록 남김 · 아래 결정 1~3 은 제안대로.

**① 그 달만 지급 방식**
- 한 사람 패널(PC) · 시트(폰) · 오른쪽 칸(태블릿) 맨 위 「이번 달 지급」 계좌 이체 / 현금. 처음엔 사람별 기본 설정 값.
- 기본과 다르게 고르면 `payroll_month_inputs.payment_method_override` 에 저장(기본과 같게 고르면 null). 한 줄 「기본은 계좌 이체 · 이번 달만 현금」 + 「기본으로」.
- `PrepRow.paymentMethod` = 그 달 값 ?? 기본, `paymentMethodDefault` = 기본. 엑셀 현금 · 이체 시트, 지급 단계 묶음, 결재 확인표, 합계가 모두 그 달 값을 따른다.
- 기본이 비어 있어도 그 달만 골랐으면 그 달 「지급 방식이 없어요」는 뜨지 않는다. 결재 요청 이후엔 다른 칸처럼 잠김. 다음 달은 다시 기본.

**② 지난달 값 가져오기**
- 급여 준비 맨 위 「지난달 값 가져오기」 → 확인 창(PC) / 하단 시트(폰): 칸을 고르고, 칸마다 몇 명이 채워지는지 보여 준다.
- 칸: 특별수당(손 입력분) · 원천세 직접 입력과 사유 · 메모 · 잔업 / 주말(손 입력분). **결정 1: 기본 체크 = 특별 · 원천세 직접 · 메모**, 잔업 · 주말은 기본 해제.
- 안 가져옴: 지난달 조정 · 연말정산 · 그 달만 지급 방식 · 고용보험 덮어쓰기(그 달에만 있는 값).
- **이번 달에 비어 있는 칸만** 채운다. 이번 달 급여 준비에 나오는 사람만(일하지 않은 사람에게 줄을 만들지 않음).
  지난달이 결재 요청 이후면 결재 때 굳힌 스냅샷 값, 아니면 지난달 입력 표.
- 끝나면 「4명 6칸 채웠어요 · 되돌리기」 — 되돌리기는 가져온 값이 아직 그대로인 칸만 비운다. audit `payroll_month_input_carry_over`.
- 코드: 순수 `src/lib/payroll-carry-over.ts`, 액션 `src/actions/payroll-carry-over.ts`(미리 세기 · 가져오기 · 되돌리기, `payroll.manage`, 잠긴 달 막힘).

**③ 급여 계좌**
- 칸: 은행 · 지점 · 종류(보통 / 당좌) · 계좌번호(숫자 7자리 — 전각 · 하이픈 · 공백 받고, 짧으면 앞을 0으로) · 명의(가타카나 — 히라가나 · 반각은 바꿔 받음).
  **결정 2: 유초은행도 이체용 지점명 · 7자리로** 적게 안내(은행 칸에 ゆうちょ 를 적으면 한 줄 안내).
- **본인**: 내 계정(모바일) › 급여 › 급여 계좌 — 시급제이거나 이미 계좌가 있으면 보인다. 바꾸면 「확인 중」.
- **관리자**: PC 근태 › 시급 패널 · 모바일 사용자 상세 급여 설정 · 급여 준비 한 사람 패널. 계좌 줄은 `payroll.view` 가 있을 때만 그린다.
  고치기 · 확인함 = `payroll.manage`. 관리자가 바꾸면 바로 확인된 계좌.
- **결정 3: 확인 전 이체는 이전에 확인한 계좌로**(`usableAccount()`). 처음부터 본인이 적은 계좌는 확인 전이라도 그 계좌를 쓴다(확인 필요는 표시).
- **확인 필요**: 「계좌 바뀜」 — 알림만(결재를 막지 않음), 급여 준비 확인 영역에서 「확인함」. 「계좌 없음」(`bank_missing`) — 이번 달 계좌 이체인데 계좌가 없으면
  `PrepIssue` 로 결재 요청을 막는다(이체할 곳이 없으므로).
- **이체 목록**(지급 단계): 사람마다 은행 지점 · 종류 번호 + 번호 복사. 확인 전이면 「확인 전 · 이전 계좌로」.
