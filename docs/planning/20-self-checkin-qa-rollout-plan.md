### 1-4. 테스트 데이터 규칙
- 실제 손님 자료로 테스트 금지(NFR-12). 테스트 예약은 Beds24 테스트 속성 또는 `is_test` 표시 → 보존 작업이 즉시 삭제.
- 여권 샘플: ICAO 9303 공개 샘플 · 자체 제작 더미(실존 번호 아님). 얼굴 동영상은 팀원 동의하에.

## 3. 운영 안내

### 3-1. 직원 교육(30분 · 병행 전 1회, 전환 때 건물마다)
1. 손님 흐름 한 번 끝까지(태블릿 데모 · 사전 등록 데모).
2. 직원 화면: 오늘 목록 · 상태 뜻(사전 등록 · 진행 중 · 체크인 됨 · 미체크인 · 기간 지남 · 인원 불일치 · 직원 확인 필요 · 확인됨) · 「확인함」 · 대리 입력 · 내보내기.
3. 현장: PIN 해제 · 재시작 · 와이파이 · 「직원에게 연락」 받았을 때 · 종이 비상 명부.
4. 하지 말 것: 손님 여권 사진을 개인 폰으로 찍기 · 태블릿에서 다른 앱 쓰기 · PIN 공유.
5. 자료: 1장짜리 요약(ko · ja) — 4단계에서 작성.

### 3-2. 현장 안내문(태블릿 옆 · 4개 언어)
- 「체크인은 이 태블릿에서 해 주세요 — 이름 + 체크인 날짜로 찾기」 · 「여권 제시는 일본 여관업법에 따른 절차이며 사본은 3년 보관됩니다」 · 「미리 등록: [QR] 고정 링크」 · 「직원 연락: 전화 · LINE · WhatsApp」 · 「별도 체크아웃 절차 없음」.
- 메시지 문안(OTA 자동 메시지 한 줄): 「도착 전 미리 등록하면 현장 체크인이 1분이면 끝나요: [고정 링크]」.

### 3-3. 장애 대응 절차(직원용)
| 증상 | 1차 조치(현장) | 2차(사무실 · 개발) |
| --- | --- | --- |
| 태블릿 화면 먹통 | 전원 길게 → 재시작(앱 자동 복귀) | 관리자 기기 목록 「마지막 접속」 확인 · 폐기 · 재등록 |
| 「지금은 체크인을 못 해요」(오프라인) | 와이파이 공유기 재시작 · 손님은 종이 비상 명부 | 서버 상태(Vercel) · Supabase 확인 |
| 손님이 예약을 못 찾음 | 이름 철자 · 날짜 확인 · 예약 번호로 · 안 되면 대리 입력 | `sync-stays` 지연 · 건물 매핑 확인 |
| 카메라 안 됨 | 「직원 확인 필요」로 진행 → 직원이 눈으로 확인 뒤 「확인함」 | 기기 교체 |
| 여권 거부 | 안내문 근거 설명 · 그래도 거부 → 「직원 확인 필요」 + 사무실 보고 | 운영 방침(회사) |
| 비밀번호가 틀림 | 건물 운영 정보(`property_operation_infos`)에서 번호 확인 · 고침 | — |

### 3-4. 정기 운영
- 매일: 직원 화면 「어제 이전 미체크인」 확인, 「직원 확인 필요」 처리.
- 매주: KPI(44 §9) 확인, MRZ 실패 사례 보기.
- 매월: 기기 목록(배터리 · 버전 · 끊김), 보존 삭제 기록 확인.
- 보건소 · 경찰 요청: 예약 찾기 → 내보내기(권한 `checkin.manage`, 기록 남음).
