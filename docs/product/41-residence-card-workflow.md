# 41. 재류카드 · 가타카나 이름 — 가입 때 받기 · A4 인쇄

> 상태: **R1 구현 완료(2026-10-22) · R2 구현 완료(2026-10-23) · R3~R4 기획**. 사용자 「너무 아날로그로 일하기 싫으니까 폴디에서 그 기능도 만들자 · 재류카드 앞뒷면을 A4 용지로 인쇄하는 기능까지」.
> 알바 급여 자동화(39 · 40)보다 **먼저** 한다 — 가타카나 이름이 명세서 · 세무사용 명세에 필요하고, 재류 정보가 甲乙丙 판단에도 쓰인다.

## 1. 지금(종이) → Foldy

| 지금 | Foldy |
| --- | --- |
| 면접 때 재류카드 앞 · 뒤를 복사기로 복사 → 종이로 사무실 보관 | **가입할 때 본인이 앞 · 뒤를 찍어 올림** → 관리자가 확인 |
| 필요할 때 서류철에서 찾음 | 사람 상세에서 바로 보기 · **A4 한 장으로 인쇄**(복사본과 같은 모양) |
| 기한 만료는 누가 따로 봐야 함 | 만료 90 · 30일 전 표시 · 만료 목록 |
| 가타카나 이름은 인사팀이 따로 적음 | 가입할 때 본인이 입력(명세서 · 세무사용 명세에 그대로) |

면접 때 카드 **실물 확인**은 그대로(본인 대조). 복사 · 종이 보관이 Foldy 로 바뀐다.

## 2. 누구에게 · 무엇을

- **이름 세 가지 + 국적 — 가입 첫 화면 하나에서**(사용자 2026-10-22 「한국어 이름이랑 영문 이름도 필요해 · 국적은 합쳐줘」):
  - 국적(맨 위, 고르면 아래 칸이 바뀜)
  - **한국어 이름** — 대한민국 국적 필수, 그 밖은 있으면. 일본 국적은 이 칸 대신 **일본어 이름(한자)**
  - **영문 이름**(로마자, 재류카드 · 여권과 같게) — 필수. 재류카드를 찍으면 카드 로마자 이름과 비교해 다르면 알려 줌
  - **가타카나 이름**(세무 · 명세서용 氏名) — 필수, 히라가나로 쳐도 가타카나로 바꿈
  - 앱에 보이는 이름 = 한국어 이름(없으면 일본어 · 영문 이름). 기본 정보 단계 수는 그대로 5.
- 국적이 일본이면 재류카드 대신 마이넘버 카드 앞면(아래 §9-7).
- **재류카드**(외국 국적 직원 전원 — 알바 · 정직원):
  - 사진: **앞면 · 뒷면**(뒷면 = 주소 변경 · 資格外活動許可 도장)
  - 입력: 카드 번호(영문 2 + 숫자 8 + 영문 2) · 재류자격(목록: 永住者 · 定住者 · 日本人の配偶者等 · 特定活動(ワーキングホリデー) · 留学 · 技術・人文知識・国際業務 · 家族滞在 · 그 밖) · 재류기간 만료일 · 就労制限 유무 · 資格外活動許可 유무
- **받지 않는 것**: 마이넘버(별도 법적 관리 — 범위 밖).

## 3. 흐름

### 3-1. 새로 가입하는 사람 (온보딩)
지금 단계(이름 → 생년월일 → 전화 → 초대 코드) **뒤에** 붙인다 — 초대 코드로 조직이 정해져야 조직 범위 저장소에 올릴 수 있다.

```
… → 초대 코드 → 가타카나 이름 → 국적 → (외국 국적) 재류카드 앞면 촬영 → 뒷면 촬영 → 카드 정보 확인 · 입력 → 완료
```

- 촬영 화면: 카드 비율(85.6 × 54mm) 틀 안내 · 카메라 / 앨범 둘 다 · 흐림 · 빛 반사 안내 문구.
- 왜 받는지 한 줄(「고용 확인 · 외국인 고용 신고에 쓰고, 관리자만 볼 수 있어요」).
- 재류카드 단계는 **나중에 하기** 가능(가입은 막지 않음) — 대신 홈에 「재류카드 등록」 카드가 남고 관리자 목록에 「미등록」.

- 시안(디자인 스킬 6종 점검 반영, 2026-10-22): https://claude.ai/artifact/FXguKLHx1kkKjJiHcHX6h1 —
  동의 체크는 **기본 꺼짐**(체크해야 「카메라 켜기」), 카메라 권한 전 안내 화면은 버튼 하나(「나중에」는 위 오른쪽 작은 글자),
  「AI가 글자를 읽는다」고 밝힘, 찍은 뒤 「읽는 중」 화면(찾은 칸마다 체크), 고르는 칸(재류자격 · 만료일 · 취로 제한 · 자격외활동)은 타이핑 대신 고르기.

### 3-1a. 카드 자동 읽기 (OCR) — R2 에 포함 (사용자 2026-10-22 「재류카드 읽는 것도 구현해야」)
- 앞 · 뒤를 찍으면 서버가 사진을 읽어 **칸을 미리 채운다** → 본인이 맞는지 보고 고쳐서 저장 → 관리자 「확인함」. 사람이 두 번 보는 구조는 그대로.
- 읽는 칸:
  - 앞면: 氏名(로마자) · 生年月日 · 性別 · 国籍・地域 · 住居地 · **在留資格** · **就労制限の有無** · **在留期間(満了日)** · 許可の種類 · 交付年月日 · **카드 번호**
  - 뒷면: 住居地 변경 기재 · **資格外活動許可欄**(허가 있음 · 내용) · 在留期間更新等許可申請欄
- 결과마다 「읽은 값 / 본인이 고친 값」을 같이 남김(고친 칸은 관리자 화면에 표시).
- 못 읽으면(흐림 · 반사) 「다시 찍기」 안내, 그래도 안 되면 손으로 입력 — OCR 이 막아도 가입은 막지 않음.
- 카드 번호 형식 검사(영문 2 + 숫자 8 + 영문 2) · 만료일이 지났으면 바로 경고.
- **API(추천)**: Claude API 이미지 읽기 — 앞 · 뒤 사진을 보내 정해진 JSON(칸별 값 · 확신도)으로 받음. 뒷면 도장 · 손글씨 칸까지 한 번에. 사람 수가 적어(입사자 월 수십 명) 비용 작음.
  대안: Google Cloud Vision(글자만 뽑고 칸 나누기는 Foldy 규칙으로) · 휴대폰 기기 안 글자 인식(앱 전용, 무료 · 사진이 밖으로 안 나감 — 웹 · PWA 는 안 됨).
  - 키는 서버 전용 환경변수(`ANTHROPIC_API_KEY`), 클라이언트에 노출 금지. 2026-06 에 업무일지용으로 뺐던 SDK 를 이 용도로 다시 들임(07-environment-setup 이력).
  - 사진이 해외(미국) 서버로 가므로 **촬영 화면에 동의 문구**(개인정보보호법 외국 제3자 제공) — 동의 안 하면 손 입력.
- **진위 확인**: 관리자 화면에 출입국재류관리청 「在留カード等番号失効情報照会」 바로가기(카드 번호 복사 버튼). (뒤 단계) 앱에서 카드 IC 칩을 NFC 로 읽어 위조 확인.

### 3-2. 이미 가입한 사람
- 앱을 열 때 가타카나 이름 · 국적이 없으면 「정보를 채워 주세요」 시트 한 번(닫을 수 있음, 다음 날 다시).
- 관리자는 사무실 종이 복사본을 **스캔해서 대신 올릴 수 있다**(사람 상세 → 재류카드 → 올리기).

### 3-3. 관리자 확인
- 사람 상세(관리자 웹 · 모바일 사용자 관리) → 「재류카드」 칸: 앞 · 뒤 사진 · 정보 · 상태.
- 「확인함」 = 사진과 입력 정보가 맞음(누가 · 언제). 틀리면 「다시 올려 주세요(사유)」 → 본인에게 표시.
- 상태: `미등록` → `확인 대기` → `확인함` / `다시 요청` · 기한 `90일 이내` · `30일 이내` · `만료`.
- 본인이 카드를 갱신하면(기한 연장 · 새 카드) 새로 올림 → 다시 `확인 대기`. 이전 카드는 이력으로 남김(§6 보관).

### 3-4. A4 인쇄 (복사본 대신)
- 사람 상세 「재류카드 인쇄」 → **A4 세로 한 장**:
  - **일본어 고정 양식**(사용자 2026-10-22). 위: 회사명 · 氏名(カタカナ) · 韓国名 · 英字氏名 · 生年月日 · 国籍 · 確認日 · 確認者
  - 가운데: **앞면 · 뒷면을 실제 카드 크기(85.6 × 54mm)** 로 위아래 — 복사기 복사본과 같은 크기. 「크게(2배)」 선택 가능
  - 아래: 카드 번호 · 재류자격 · 만료일 · 就労制限 · 資格外活動許可 · 인쇄 일시 · 인쇄한 사람
- **여러 명 한 번에**: 재류카드 목록에서 체크 → 한 사람당 한 장씩 이어서 인쇄(PDF 하나).
- 방식: 브라우저 인쇄(`@page A4 portrait`) + PDF 저장. 표 내보내기가 아니라 서류 인쇄라 Excel 은 없다(콘솔 규칙 4b 의 Excel + PDF 쌍은 표 내보내기용).
- 인쇄할 때마다 기록(누가 · 언제 · 누구 것) — 개인정보 서류라 출력 이력을 남긴다.

### 3-5. 목록 · 알림
- 관리자 웹 「직원 서류」(사용자 아래): 사람 · 국적 · 재류자격 · 만료일 · 상태 · 인쇄 — 만료 가까운 순.
- 만료 90 · 30일 전 본인 · 담당자에게 알림(알림은 막바지 일괄 구현 때 — `notification-batch-policy`).
- (뒤 단계) 留学 등 資格外活動이면 **주 28시간** 넘을 때 근태에서 경고.

## 4. 권한

- **새 키 `staff_documents.view`(직원 서류 보기 · 인쇄 · 확인)** — 기본 대표 · 전무(개발자는 항상). 인사 담당 등은 사람마다 켬.
- 본인은 자기 카드만 올리기 · 보기. 다른 사람 것은 위 키 없이는 서버가 막음(UI 숨김만으로 막지 않는다).
- 가타카나 이름 · 국적은 급여 담당(`wages.manage` · `payroll.view`)도 봄 — 명세서에 필요.

## 5. 저장 · 보안

- 사진: **새 비공개 버킷**(예 `staff-documents`), 경로 `org/{조직}/user/{사람}/residence/{카드id}-{front|back}.jpg`. 공개 URL 없음, 볼 때마다 짧은 서명 URL.
- 저장소 규칙: 본인 경로 올리기 · 읽기 + `staff_documents.view` 가진 같은 조직 사람 읽기. 다른 기능 사진과 섞지 않는다.
- 이미지: 클라이언트 압축(기존 정책)하되 **글자가 읽히게** 긴 변 2000px · 품질 높게. 장수 = 앞 · 뒤 2장(5장 제한 안).
- 데이터(설계 개요):
  - `profiles` 에 `name_ko` · `name_ja` · `name_en` · `name_katakana` · `nationality` (기존 `name` = 앱에 보이는 이름)
  - `staff_residence_cards`(조직 · 사람 · 카드 번호 · 재류자격 · 만료일 · 就労制限 · 資格外活動 · 앞/뒤 경로 · 상태 · 확인자 · 확인 시각 · 요청 사유 · 지금 카드 여부)
  - `staff_document_print_logs`(조직 · 인쇄한 사람 · 대상 · 시각)
- RLS: 조직 범위 + 본인 / `staff_documents.view`.

## 6. 보관 · 삭제

- 재직 중: 지금 카드 + 이전 카드(갱신 이력).
- **퇴사 후 3년 뒤 삭제**(사진 · 카드 정보 · 인쇄 기록) — 하드 삭제(지금 삭제 정책과 같음). 자동 정리 작업으로.
- 종이 복사본: Foldy 로 옮긴 뒤엔 보관하지 않는 것을 추천(파쇄) — 사용자 결정.

## 7. 화면 (폰 · 폴드 · 태블릿 · PC)

- 모바일 온보딩 단계 추가(지금 온보딩 디자인 그대로) · 촬영 화면.
- 모바일 「내 정보」 → 재류카드(내 카드 보기 · 다시 올리기).
- 관리자 웹: 사용자 패널에 「재류카드」 칸 · 「직원 서류」 목록 · 인쇄 화면.
- 모바일 사용자 관리(`/mobile/users`) 상세에도 같은 칸(폴드 · 태블릿 대응).
- 문구 ko · ja · en.

## 10. R2 구현 (2026-10-23)

- **화면** `/account/id-card` — 셸 없는 전체 화면. 국적이 JP 면 마이넘버 카드 앞면 1장, 그 밖은 재류카드 앞 · 뒤 2장.
  - 들어오는 곳: 가입 완료 화면의 「Foldy 시작하기」(조직에 들어온 경우 `?from=onboarding&next=…` 로 거쳐 감) · `/mobile` 하루 한 번 안내 시트
    (이름이 다 찼고 서류가 없을 때, 「나중에」는 이름 안내와 따로 기억 — `foldy.idCardPrompt.dismissedOn`) · 내 정보(모바일) 조직 칸의 「재류카드 / 마이넘버 카드」 줄(상태 표시).
  - 순서: 안내 · 동의(기본 꺼짐) → 촬영(앞 → 뒤) → 읽는 중 → 확인 · 고치기 → 완료. 동의하지 않으면 「동의하지 않고 계속」 → 사진만 찍고 직접 입력.
  - 촬영: 앱 안 카메라(뒤 카메라) · 카드 비율 틀 · 틀 안만 잘라 긴 변 2000px JPEG(0.92). 카메라를 못 쓰면 앨범만. 시안의 「카드를 찾으면 자동 촬영」 · 플래시는 뒤로 미룸(셔터 누르기).
  - 확인 화면: 고르는 칸(재류자격 · 취로 제한 · 자격외활동 · 성별)은 아래 시트, 날짜는 기기 날짜 입력, 글자가 흐린 칸은 노란 줄 「카드와 같은지 봐 주세요」, 만료일이 지났으면 경고(저장은 막지 않음), 고친 칸은 「고침」.
  - 이미 등록한 사람이 열면 지금 카드(상태 · 사진 · 칸 · 다시 요청 사유)를 보여 주고 「새 카드로 다시 등록」.
  - 폴드(≥600): 확인 화면 사진 왼쪽 · 칸 오른쪽. 태블릿(≥1000): 촬영 화면 오른쪽에 단계 칸(시안 W2).
- **읽기**: Claude API(`claude-opus-5-5`, effort low, 정해진 JSON). 칸마다 값 + 확신 여부. 재류카드가 아니면 · 흐리면 다시 찍기 안내, 그 밖 실패는 직접 입력으로.
  마이넘버 사진에 12자리 개인번호가 보이면 **그 사진을 저장소에서 지우고** 앞면을 다시 찍게 한다. 안전 분류기 거절 대비 서버 쪽 대체 모델(`fallbacks: "default"`).
  키 `ANTHROPIC_API_KEY`(서버 전용, `docs/engineering/07-environment-setup.md`). 한 장 읽기 비용은 몇 엔 수준.
- **동의 문구(사실대로)**: 「사진을 미국 AI 서버(Anthropic)로 보냄 · AI 학습에는 쓰이지 않음」, 자세히: 「Anthropic 은 안전 점검을 위해 최대 30일 보관 뒤 지움 · 원본은 Foldy 비공개 저장소」.
  (시안의 「그 서버에는 남지 않아요」는 사실과 달라 바꿈.)
- **저장**: 표 `staff_id_documents`(§5 의 `staff_residence_cards` 를 마이넘버까지 담게 이름을 바꿈) — 칸 · 읽은 값(`ocr_values`) · 고친 칸(`edited_fields`) · 상태 · 확인자.
  갱신하면 새 행, 이전 행은 `is_current=false` 이력. 사진은 비공개 버킷 `staff-documents` 의 `{조직}/{본인}/{서류id}/{front|back}-{임의}.jpg` —
  다시 찍을 때마다 새 이름, 등록할 때 쓰지 않은 사진은 지운다. 보기는 서버가 만든 10분 서명 URL 만.
- **관리자**: 사용자 패널(PC) · 모바일 사용자 관리 상세에 「신분 서류」 칸 — 앞 · 뒤 사진(누르면 크게) · 칸 · 만료까지 남은 날(90 · 30일 · 만료) ·
  AI 읽기 / 직접 입력 · 본인이 고친 칸 · 「확인함」 / 「다시 요청(사유)」 · 카드 번호 복사 + 출입국재류관리청 失効情報照会 바로가기.
  `staff_documents.view`(기본 대표 · 전무) 가 없으면 서버가 이 칸 데이터를 아예 싣지 않는다. 「다시 요청」 사유는 본인 화면에 노란 줄로 보인다.
- 알림(확인 · 다시 요청 · 만료)은 막바지 일괄 구현 때(`notification-batch-policy`). 완료 화면 문구도 「알려 드려요」 대신 「상태가 바뀌어요」.
- 코드: `src/app/account/id-card/*` · `src/components/identity/id-card-{flow,camera}.tsx` · `id-document-panel.tsx` · `src/lib/staff-documents/{fields,ocr,server}.ts` ·
  마이그레이션 `202610230001_staff_id_documents.sql`(운영 적용) · 테스트 `staff-document-fields.test.ts`.
- 남은 것: 실제 폰에서 카메라 · 읽기 확인, 자동 촬영(카드 감지), 관리자 대신 올리기(§3-2 스캔본) — R4 목록과 함께.
