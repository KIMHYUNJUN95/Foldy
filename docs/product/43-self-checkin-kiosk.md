# 43. 셀프 체크인 — 건물 태블릿 (기획 초안)

> 상태: **기획 초안(2026-10-29) · 코드 미착수 · 큰 결정 2개 대기(§6)**.
> 회사 의뢰(사용자 전달 2026-10-29): 각 건물에 있는 우리 태블릿에서 손님이 스스로 체크인하는 기능. 지금 체크인은 **Hotelsmart** 가 맡고 있다
> (01 「2026-10-21 청소 배정을 Foldy 로」 — 「체크인은 Hotelsmart 유지」). 이 기능이 생기면 체크인도 Foldy 로 옮겨 온다.

## 1. 범위

- **한다**: 태블릿에서 예약 찾기 → 숙박자 명부 입력 → 본인 확인 → 완료 안내. 관리자가 명부 · 여권 사본을 보고 보관 기간을 지키는 것까지.
- **안 한다(사용자 지시)**: 직원 상주 · 긴급 출동(10분 이내 도착) 같은 인력 체계. 여기서는 셀프 체크인 기능만 다룬다.
- 허가: **전 건물 여관업법(旅館業法)** — 주택숙박사업법(민박) 건물 없음(사용자 확인 2026-10-29).
- 지역: 신주쿠구 — 신주쿠 보건소 기준을 따른다.

## 2. 법 요건 (2026-10-29 조사 — 최종 기준은 보건소 허가 서류)

| 요건 | 내용 | 근거 |
| --- | --- | --- |
| 숙박자 명부 | 이름 · 주소 · 연락처 · 도착 · 출발일. 일본에 주소가 없는 외국인은 **국적 · 여권 번호** | 旅館業法施行規則 4조의2 (교토시 안내) |
| 여권 사본 | 외국인 손님 여권 사본을 명부와 함께 **3년 이상** 보관. **전자 보관 가능**(2025-04 개정에서 명시) | 후생노동성 衛生等管理要領 개정 |
| 본인 확인 | 영상으로 직원이 확인하는 방식에 더해 **자동 체크인 기기로 정보를 맞춰 보는 방식**도 인정(2025-04-01 시행) | 같은 개정 |
| 영상(ICT) 확인 조건 | 얼굴과 여권이 화면에 선명히 보이고, 영상이 **시설 근처에서** 보내진 것임을 확인할 수 있을 것 | 후생노동성 · 가나가와현 안내 |
| 신주쿠구 | 영업자가 **직접 설치한 기기**로 본인 확인 · 출입 확인. 공식 안내문 본문은 아직 못 읽음 — 행정서사 글로 확인 | 아래 출처 |

**할 일**: 회사가 각 건물 허가 때 보건소에 낸 「현관 장부(玄関帳場) 대체 방법」 서류를 받아 본다. 지금 Hotelsmart 가 그 방식으로
승인돼 있으므로 **우리 화면도 같은 방식을 그대로 따라야** 한다(바꾸려면 보건소와 다시 상의).

## 3. Beds24 데이터로 할 수 있는 것

예약은 이미 Beds24 웹훅으로 `reservations` 에 들어온다(원본은 `raw_payload`). 최근 60일 확정 예약 2,316건에서 항목이 채워진 비율
(2026-10-29 운영 DB 집계, 값은 보지 않고 개수만):

| 항목 | 채워진 비율 | 쓸 곳 |
| --- | --- | --- |
| 인원 `numAdult` | 100% | 몇 명분 명부를 받을지 |
| 이름 `firstName` · `lastName` · 도착일 · 예약 번호 | 91% | 예약 찾기 · 대표자 이름 미리 채우기 |
| 채널 예약 번호 `apiReference` | 90%(Airbnb · Booking.com) | 손님이 아는 번호로 찾기 |
| 언어 `lang` | 69% | 태블릿 첫 화면 언어 고르기 |
| 국가 `country` · `country2` | 52~65% | 국적 미리 채우기(손님이 고칠 수 있게) |
| 전화 `phone` | 60% | 연락처 미리 채우기 |
| 이메일 `email` | 41%(Airbnb 는 없음) | 미리 입력 링크 보내기 — 절반 이상 못 보냄 |
| 주소 `address` | 6% | **거의 없음 → 손님이 입력해야 함** |
| 여권 번호 · 동행자 | 없음 | **손님이 입력해야 함** |

**결론**: Beds24 는 **예약 찾기 · 인원 · 대표자 이름 · 날짜 · 방**을 맡기기에 충분하다. 손님이 직접 입력하는 칸이 크게 줄고,
「누가 · 몇 명 · 어느 방 · 언제」는 Beds24 값을 그대로 쓴다. 다만 **주소 · 여권 번호 · 동행자 명부 · 여권 사진**은 Beds24 에 없어서
손님이 입력해야 한다. 이메일이 41% 뿐이라, 미리 입력 링크를 보낸다면 Beds24 메시지(채널 메시지)로 보내야 한다.

- 체크인이 끝났을 때 Beds24 예약 상태를 바꿀지(쓰기)는 따로 정한다. Beds24 쓰기는 위험 영역이라(CLAUDE.md 「Beds24」) 처음에는 **Foldy 안에서만** 체크인 완료를 기록하는 쪽을 추천한다.

## 4. 흐름 (초안 — 본인 확인 칸은 비워 둔다)

1. **예약 찾기** — 예약 번호 · 이름 + 날짜 · QR(미정 §6-3). 그 건물의 오늘 도착 예약만 찾는다.
2. **명부 입력** — 대표자는 Beds24 값으로 미리 채움, 인원수만큼 동행자 칸. 외국인이면 국적 · 여권 번호 필수.
3. **본인 확인** — **갈아 끼우는 칸**. 방식이 정해지면(§6-1) 이 단계만 바꾼다. 그 전까지는 「여권 · 얼굴 사진 찍어 저장」(C)으로 칸을 채워 두되,
   보건소 허가 방식과 맞는지 확인하기 전에는 운영에 쓰지 않는다.
4. **완료** — 방 번호 · 이용 안내(출입 방법은 미정 §6-4).

화면 원칙: 손님용 화면은 직원 화면(`/mobile` · `/admin`)과 분리된 **키오스크 화면**. 태블릿은 건물에 고정된 기기로 등록하고, 손님은 로그인하지 않는다.

## 5. 데이터 · 보안 메모 (설계 때 자세히)

- 여권 사진 · 여권 번호는 민감 정보 — 조직 격리 RLS, 비공개 저장소, 서비스 롤은 서버에서만, 관리자 열람 권한 키 따로.
- 보관: 체크아웃 뒤 **3년** 지나면 지우는 규칙(삭제 정책 결정 필요 — 여관업법 보관 의무라 지금의 「사용자가 지우면 바로 삭제」와 다름).
- 개인정보처리방침에 숙박자 명부 · 여권 사본 조항 추가(19 C7 법무 검토와 같이).
- 태블릿 기기 인증은 근태의 「기억된 기기」(`attendance_trusted_devices`)처럼 체크인만 허용하는 기기 토큰 방식을 참고.

## 8. 정한 것 (사용자와 정한 순서대로)

### 8-1. 태블릿 = 회사가 직접 산 Android 태블릿 (2026-10-30)

- 건물에 있는 태블릿은 **Hotelsmart 가 준 기기가 아니라 회사가 직접 산 것** → 우리가 자유롭게 앱을 깔고 잠글 수 있다. Hotelsmart 를 끊어도 기기는 남는다.
- 기종은 **Android 로 보임**(사용자 「안드로이드인 것 같아」 — 정확한 기종 · OS 버전 · 카메라 화질은 **현장 확인 필요**, 7-2 기기 등록 설계 전에).
- 뜻: 손님 화면은 **Foldy Android 앱(Capacitor) 의 키오스크 모드** 또는 Chrome 키오스크 웹 둘 다 가능. 앱이면 카메라 · 화면 잠금(Android 「앱 고정」 · 전용 기기 모드) · NFC(나중에 여권 IC 칩)까지 열린다.
- 확인할 것(👤): 기종 · Android 버전 · 전면 카메라 화소 · 충전 상태 · 와이파이 · 건물마다 1대인지.

### 8-2. 지금 Hotelsmart 첫 화면 — 언어 4개 · 그 뒤는 미확인 (2026-10-30)

- 첫 화면: 「Welcome · 言語を選択してください」 → **日本語 · English · 简体中文 · 한글** 4개 버튼. 세로 화면, 사진 배경, 하단 HOTEL SMART 로고.

- Hotelsmart 공개 자료(2026-10-30 조사)로 추정한 일반 흐름: 예약 뒤 메일 · SMS 링크로 **사전 등록**(마이페이지) → 당일 입구 태블릿에서 **QR 스캔** 체크인(최단 10초).
  우리 건물에서 사전 등록을 쓰는지, QR 없이 태블릿에서 직접 입력하는지는 **미확인**. 여권 촬영 · 본인 확인 단계는 공개 자료에 없음.

### 8-3. 출입 = 객실 문 옆 키박스(열쇠) 또는 도어락 — 둘 다 번호 (2026-10-30)

- 건물 · 객실마다 둘 중 하나: **열쇠 객실** → 객실 문 바로 옆에 **키박스**(번호를 눌러 열고 열쇠를 꺼냄) / **나머지** → 문에 **도어락**(번호 입력).
- 뜻: 어느 쪽이든 손님에게 필요한 건 **「방 번호 + 그 방의 번호(키박스 또는 도어락)」** 한 쌍이다. 완료 화면(7-12)은 이 두 가지를 크게 보여 주면 된다.
  스마트락 API 연동은 지금 범위에 없다(7-13) — 번호를 **보여 주는 것**까지가 체크인의 끝.
- 객실 마스터(`rooms`)에 **출입 방식(키박스 · 도어락) 과 번호**를 들고 있어야 한다. 번호가 손님마다 바뀌는지 · 고정인지, 지금 누가 어떻게 알려 주는지는 다음 질문(§8-4).

### 8-4. 번호는 방마다 고정 (2026-10-30)

- 키박스 · 도어락 번호는 **방마다 고정**(손님마다 바꾸지 않음) → 예약별 번호 발급 · 직원이 번호 바꾸는 흐름은 **필요 없다**.
- 이미 있는 자리: `property_operation_infos.shared_access`(건물 공용 출입) · `room_access`(객실별 출입) jsonb — 관리자 · 모바일 캘린더가 쓰는 건물 운영 정보(04 「property_operation_infos」).
  셀프 체크인 완료 화면은 **이 값을 그대로 읽어** 보여 준다. 새 표를 만들지 않고, 필요하면 여기에 「출입 방식(키박스 · 도어락)」 구분만 보탠다.
- 고정 번호라서 **완료 화면 노출 시간 · 다시 보기** 가 중요하다: 손님이 화면을 떠난 뒤 번호를 잊으면 다시 찾을 길이 있어야 한다(예약 찾기 → 「이미 체크인함 → 번호 다시 보기」, 7-4 · 7-12 에서 정함).
- 보안 메모: 번호가 고정이라 **한 번 체크인한 예약만** 보여 주고, 화면은 일정 시간 뒤 자동으로 첫 화면으로 돌아간다.

### 8-5. 비밀번호는 OTA 자동 메시지로 이미 전부 보내고 있다 (2026-10-30)

- 예약이 들어오면 **OTA(Airbnb · Booking.com) 자동 메시지**에 도어락 · 키박스 비밀번호를 **전부** 함께 보낸다. 태블릿 끝 화면에 나오는지는 미확인(👤 §8-2 현장 확인에 포함).
- 뜻 ①: 손님은 **태블릿을 거치지 않아도 방에 들어갈 수 있다** → 셀프 체크인은 출입을 막는 장치가 아니라 **법이 요구하는 명부 · 본인 확인을 받는 절차**다.
  그래서 「체크인 안 한 손님」이 생긴다 — 직원 화면(7-15)에 **오늘 도착 중 미체크인 목록**이 꼭 있어야 하고, 현장 안내(스티커 · 메시지 문구)로 태블릿 체크인을 유도해야 한다.
  비밀번호를 태블릿 체크인 뒤에만 주는 쪽으로 바꾸는 건 운영 방식 변경이라 **회사 결정 사항**(7-4 · 7-12 에서 선택지로만 적어 둔다).
- 뜻 ②: 자동 메시지가 이미 있으므로 **「도착 전 미리 입력」 링크(⏸ 7-9)를 그 메시지에 한 줄 보태는 길**이 가장 싸다. Beds24 자동 메시지인지 OTA 쪽 설정인지는 확인 필요(👤).
- 뜻 ③: 완료 화면(7-12)의 비밀번호는 「다시 알려 주기」 성격 — 메시지를 못 본 손님을 위해 보여 주되, 이미 받은 정보라 노출 위험은 낮다.

### 8-6. Hotelsmart 관리자 화면을 직접 읽음 — 지금 실제 체크인 방식 (2026-10-30, 앱 안 브라우저 · 읽기만)

### 8-7. 본인 확인 = 확인 동영상 촬영 저장 — Hotelsmart 와 같은 방식 (2026-10-30, 사용자 「같은 방식으로」)

- 첫 버전의 본인 확인은 **여권 촬영 뒤 손님 얼굴을 동영상으로 찍어 저장**(Hotelsmart 「確認動画撮影」과 같음). 길이는 **5초 × 숙박자 수**를 기본값으로 하고 건물 설정에서 바꿀 수 있게.
- 저장 뒤 **직원 기기(모바일 · PC)에 실시간 알림**(Hotelsmart 「リアルタイム確認」에 해당) — 알림은 막바지 일괄 구현 방침(7-21)이라 **요건만 적고 구현은 그때**. 그 전까지는 직원 화면의 「오늘 체크인」 목록이 대신한다.
- 직원은 명부 · 여권 사진 · 동영상을 한 화면에서 보고 **「확인함」** 표시를 남긴다(누가 · 언제 — 7-22). 확인 전이라도 손님 입실은 막지 않는다(§8-5 — 비밀번호는 이미 손님에게 있음).
- A(직원 영상 통화) · B(여권 판독 + 얼굴 자동 대조)는 **건물 설정의 선택지**로 자리만 두고 나중에 붙인다. 보건소 허가 서류에 다른 방식이 적혀 있으면 그 방식으로 바꾼다(👤 회사 확인 — 19 A8 은 이 확인으로 축소).
- 영상 · 여권 사진은 **비공개 저장소**, 명부와 함께 **3년 보관**(7-16), 열람 권한 따로(7-15).

### 8-8. 명부 입력 = 도착 전 링크로 미리 + 태블릿에서 마무리 (2026-10-30, 사용자 「미리 + 태블릿」)

### 8-11. 동행자 = 전원 명부 · 외국인은 전원 여권 (2026-10-30, 사용자 「전원 받기」)

- 예약 인원(Beds24 `numAdult` + `numChild`)만큼 **명부 줄을 미리 만든다**. 대표자 줄은 Beds24 값으로 미리 채우고, 나머지는 손님이 채운다. 인원이 예약과 다르면 손님이 줄을 더하거나 빼되, **줄 수 ≠ 예약 인원이면 직원 화면에 표시**(인원 초과 · 미달 확인).
- **외국인(일본 주소 없음)은 전원 여권 사진 + 여권 번호**. 일본 거주자는 이름 · 주소 · 연락처만(여권 불요).
- **어린이**: 구분(성인 · 어린이)을 두고, 어린이도 이름 · 국적 · 생년월일은 받는다. 어린이의 여권은 **「있으면 찍기」**(외국인 어린이도 여권이 있으므로 원칙 요구, 없으면 보호자가 「동반 어린이 · 여권 없음」 체크 → 직원 확인 표시). 연락처는 대표자 것으로.
- **대표자만 받는 칸**: 연락처(전화 · 이메일) · 주소(같은 주소면 「대표자와 같음」 한 번 누르기) · 약관 동의(대표자가 전원 대신).
- 얼굴 동영상(§8-7)은 **전원**(5초 × 인원 — 한 번에 여러 명이 화면에 들어와도 됨).
- 사전 등록(§8-8)에서 대표자가 전원 분을 미리 넣을 수 있다. 태블릿에서는 **사람별 탭**으로 하나씩 확인 · 보충.
- 직원 화면(7-15) 에는 사람별 「명부 완료 · 여권 있음 · 확인됨」 상태.

| 인원이 예약과 다름 | 막지 않음, 손님이 줄 추가 · 삭제 | 「인원 불일치」 표시(§8-11) |
| 숙박비 미결제 | **막지 않음**(결제는 OTA · 별도, 이 기능 범위 밖) | — |

- 「체크인 됨」의 정의 = **전원 명부 저장 + 동영상 저장 + 약관 동의** 세 가지가 끝난 시각. 그 전은 「진행 중」.

### 8-13. 여러 방 예약 — 한 번에 체크인, 방마다 명부 (2026-10-30, 사용자 「초안대로」)

- 실제 빈도(운영 DB, 최근 180일 비취소): 방 1개 7,016건 · 2개 17건 · 3개 1 · 4개 1 · 5개 1 → **0.3%**. 흔하지 않지만 생긴다.
- 설계: 코드 · 이름으로 찾으면 같은 채널 예약 번호(`original_reservation_id`)의 **방 전부를 한 화면에** 보여 주고, 손님이 **방마다 사람을 배정**해 명부를 채운다(방 A 2명 · 방 B 3명). 동영상은 한 번(전원). 완료 화면에 **방마다 번호 · 비밀번호**.
- 체크인 코드는 **그룹에 하나**(방마다 따로 주지 않음). 방 하나만 먼저 쓰고 나머지는 나중에 와도 「이미 체크인함 → 명부 보충」으로 이어서 할 수 있다.
- Beds24 그룹 충돌 키(`::bid::`)가 붙은 예약도 같은 묶음으로 본다(01-beds24 「Group bookings」).

### 8-14. 보관 · 삭제 = 체크아웃 뒤 3년 보관, 자동 삭제, 그 전엔 못 지움 (2026-10-30, 사용자 「그렇게」 — 삭제 정책 예외 승인)

> Foldy 기본 삭제 정책(사용자가 지우면 즉시 하드 삭제, CLAUDE.md 9)의 **승인된 예외**. 범위는 `checkin` 스키마의 명부 · 여권 사진 · 얼굴 동영상 · 약관 동의 기록 · 사전 등록 입력뿐. 다른 엔티티로 넓히지 않는다.

- **보관 기간**: 체크아웃 날짜(도쿄) 기준 **3년**. `retain_until = check_out_date + 3년` 을 저장할 때 계산해 둔다.
- **자동 삭제**: 매일 새벽(도쿄) 작업이 `retain_until` 이 지난 것을 지운다 — 저장소 파일(여권 · 동영상) 먼저, 다음 줄. 지운 뒤 「예약 번호 · 지운 시각 · 건수」만 남는 삭제 기록(개인 정보 없음).
- **3년 전 삭제 금지**: 직원 화면에 삭제 버튼 없음. 서버 액션에도 삭제 경로 없음(RLS 도 delete 정책 없음). 잘못 찍은 사진은 **「다시 찍기 → 새 파일이 현재본」**, 이전 파일은 「대체됨」으로 남겨 3년까지 보관.
- **내보내기**: 예약 단위 「명부 PDF + 여권 사진 묶음(zip)」 — 보건소 제출 · 경찰 조회 대응. 열람 권한(7-15)과 별도의 **내보내기 권한**, 내보낸 기록(누가 · 언제 · 어느 예약 — 7-22). 4b 규칙(Excel + PDF 같이)은 **명부 표**에는 적용(Excel + PDF), 사진 묶음은 zip.
- **손님 삭제 요청**: 법정 보관 기간 안에는 못 지운다는 문구를 개인정보처리방침 · 사전 등록 페이지 안내에 넣는다(7-23).
- **저장소**: 비공개 버킷 `checkin-documents`(서비스 롤로만), 경로 `org/예약/사람/종류/파일`. 서명 URL 은 짧게(열람 때 1~5분). 클라이언트 압축은 여권 사진에 적용(글자가 읽히는 수준 유지 — 긴 변 2,000px 안팎), 동영상은 태블릿에서 저해상도(720p · 5초 × 인원)로 찍어 용량을 줄인다.
- 예약이 **취소**되면 명부가 있어도 숙박이 없으므로 보관 의무가 없다 → 취소 확정 30일 뒤 삭제(사전 등록 자료 포함).

### 8-15. 기기 등록 · 잠금 (2026-10-30, 초안)

- **등록**: 직원이 Foldy 관리자(권한 `checkin.manage`)에서 「태블릿 등록 코드」(한 번 쓰는 8자리 · 10분 유효)를 만든다 → 태블릿 앱 첫 화면에서 코드 입력 → 서버가 **기기 토큰**(원문은 기기에만, 서버는 sha256 해시 — 근태 「기억된 기기」와 같은 방식)을 발급하고 **건물 하나**에 묶는다. 이후 모든 요청은 이 토큰으로만. 기기 목록 · 이름(「Kabukicho 1층」) · 마지막 접속 · 폐기는 관리자 화면.
- **잠금**: Android **「앱 고정(Screen pinning)」 + 키오스크 모드**(Capacitor 플러그인 · 전용 런처 설정) — 홈 · 뒤로 · 알림 막음. 화면 켜짐 유지, 밝기 고정. 직원 해제는 **긴 누름 5초 + 직원 PIN**(건물별 PIN, 관리자에서 바꿈).
- **세션**: 손님 한 팀 = 세션 하나. 무조작 **30초(완료 화면) · 240초(입력 중)** 뒤 처음으로 돌아가며 입력 중이던 것은 서버에 「진행 중」으로 남겨 이어서 할 수 있다(§8-12). 처음 화면으로 돌아갈 때 화면 · 카메라 버퍼 · 입력값을 모두 비운다.
- **카메라**: 전면 카메라만. 촬영 전 미리보기, 촬영 후 「다시 찍기」. 여권은 자동 테두리 인식 없이도 되게(1차는 손님이 맞춰 찍음), 글자 판독(OCR)은 2차.
- **업데이트**: 앱은 배포된 웹을 띄우는 Capacitor 셸이라 화면은 Vercel 배포로 바뀐다. 셸 업데이트는 APK 를 관리자가 설치(스토어에 안 올림 — 사내 기기라 사이드로드).
- **요건 대응**: 「영업자가 직접 설치한 기기」 = 기기 토큰으로 건물에 묶인 등록 기기에서만 체크인이 되므로, 손님 휴대폰으로는 태블릿 단계(동영상)를 못 한다. 사전 등록 페이지는 명부 · 여권만.

### 8-20. Hotelsmart 전환 — 한 건물 2주 병행 → 전 건물, 기존 명부는 내보내서 보관 (2026-10-30, 사용자)

- **순서**: 건물 하나(체크인 수 적당 · 직원이 자주 가는 곳 — 👤 고르기)에서 **2주 병행**: 태블릿은 우리 앱, Hotelsmart 는 켜 둔 채 **명부 건수 · 내용 비교**(청소 배정 전환과 같은 방식). 문제 없으면 나머지 건물 순서대로. 건물마다 Hotelsmart 「タブレット表示設定」을 끄고 우리 기기 등록(§8-15).
- 병행 중 손님에게는 **우리 태블릿 하나만** 보이게(두 대 놓지 않음). Hotelsmart 쪽은 직원이 비교용으로만.
- **기존 명부 가져오기(2026-10-30 Hotelsmart 화면 확인)**:
  - **글 명부는 한꺼번에 내보낼 수 있다** — 「帳票・CSV出力 → 旅館業法対応_帳票 → **宿泊者台帳**」: 건물 · 기간(체크인 · 체류일 · 체크아웃 기준) 지정 → CSV. 예약 단위로도 「宿泊者台帳 → 書き出し CSV · Excel」.
  - **여권 사진 · 동영상 · 서명 이미지는 한꺼번에 내보내는 메뉴를 못 찾았다** — 예약 상세 「宿泊者画像」에서 하나씩만 보임. 호스트 기기 알림 종류에 「宿泊者情報ダウンロード」가 있어 **일괄 내려받기 작업이 따로 있을 수 있다** → 👤 Hotelsmart 지원에 「해지 전 숙박자 이미지 일괄 내려받기」 가능한지 문의. 안 되면 **해지하지 말고 열람 전용으로 유지**하거나(비용 확인) 3년치를 사람이 내려받는다.
  - 가져온 것은 **우리 DB 에 넣지 않는다**(이관 아님). 3년 보관 의무용 **보관함**(비공개 저장소 `checkin-archive/hotelsmart/건물/연도/`)에 파일 그대로 두고, 직원 화면에 「Hotelsmart 시절 명부(파일)」 링크만. 넣어서 합치려면 칸 대응 · 중복 · 검증이 커서 첫 버전 범위 밖.
- **해지 시점**: 전 건물 전환 + 이미지 내려받기 확인 뒤. Hotelsmart 가 유일한 Beds24 사이트 컨트롤러 연동이지만 우리 Beds24 연동과는 **별개**라 해지해도 Foldy 예약 흐름 영향 없음(§8-6(1)).
- 청소 배정(37)도 Hotelsmart 병행 중이므로 **같은 건물에서 같은 시기에** 맞추면 비교 작업이 한 번에 끝난다.
