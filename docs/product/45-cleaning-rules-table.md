# 45 · 청소 상황표 (기준표)

2026-11-04 사용자 확정. 청소 · 배정 동작의 **기준**이다. 코드 · 자동 테스트 · 데모 확인은 이 표의 줄을 그대로 따른다.
규칙을 바꾸면 이 표를 먼저 고치고 사용자 확인을 받는다. 세부 화면 설명은 문서 07 · 37.

왜 만들었나: 점검 수정(A · B · C1)을 지적받은 자리에서만 하다 보니, 같은 규칙을 따로 판단하는 다른 곳이 남아 수정마다 새 문제가 나왔다.
이제 판단은 공용 함수 한 곳에서 하고, 화면 · 서버 · 다른 기능은 그 결과만 쓴다.

## 1. 방이 어떻게 보이고 시작되나

| ID | 상황 | 하루 보기 | 알바 시작 |
|---|---|---|---|
| R1 | 오늘 체크아웃, 기록 없음 | 대기 | 됨 |
| R2 | 지난 날 못 한 방을 오늘 볼 때 | 「N일째」 | 됨 |
| R3 | 지난 방 + 오늘 체크아웃 | 한 줄, 「N일째」 표시 | 됨 |
| R4 | 오늘 방이 안 끝난 채 내일(앞날)을 볼 때 | 그날 체크아웃과 그날로 미룬 방만, 아직 안 끝난 방은 밀려 오지 않음. 단 그날 이미 넣어 둔 배정이 있는 안 끝난 방은 남기고, 이미 청소돼 필요 없어진 방의 배정은 관리자가 정리하도록 「취소됨」으로 남긴다 | 해당 없음 |
| R5 | 어제 한 명만 끝낸 2인 방 | 치운 방으로 보고 다음 날 안 나옴 | 해당 없음 |

| R7 | 오늘 미룸 | 「N일로 미룸」, 되돌리기 있음 | 막음 |

| R9 | 미룬 기간 중 새 체크아웃 발생(미룬 날 뒤의 체크아웃) | 대기 | 됨 |

| R11 | 기간 지난 방을 다시 미룸 | 오늘 목록에 남고 되돌리기 됨 | 막음 |
| R12 | 처리 끝 | 끝남, 되돌리기 있음 | 막음 |
| R13 | 배정 뒤 예약 취소 | 「취소됨」, 알바에게는 흐리게 | 막음 |

## 2. 배정을 바꿀 수 있나

**기록이 있는 사람은 그 방에서 빠지지 않고, 기록이 없는 사람은 옮길 수 있다.** 기록 = 그 방 그날의 진행 중 · 완료 기록(취소 · 처리 끝 제외).

| ID | 방 상태 | 사람 넣기 | 기록 없는 사람 빼기 · 교체 | 기록 있는 사람 빼기 · 교체 | 미루기 · 처리 끝 | 방 추가 |
|---|---|---|---|---|---|---|
| A1 | 대기 | 됨 | 됨 | 해당 없음 | 됨 | 됨 |
| A2 | 청소 중 | 막음 | 됨 | 막음 | 막음 | 막음 |
| A3 | 1/2 끝남 | 막음 | 됨(빼면 「끝남」) | 막음 | 막음 | 막음 |
| A4 | 끝남 | 막음 | 됨 | 막음 | 막음 | 막음 |
| A5 | 미룸 · 처리 끝 | 막음 | 해당 없음 | 해당 없음 | 되돌린 뒤 | 막음 |
| A6 | 예약 취소됨 | 막음 | 빼기만 됨, 교체 창에서 잠금 | 막음 | 해당 없음 | 수기 방으로 추가 됨 |

- A7 **일정 취소(취소 요청 수락 포함):** 그 사람이 그날 청소 중이면 막고 「청소 중인 방이 있어요」를 띄운다. 끝낸 방의 배정은 남기고, 아직 시작하지 않은 방만 뺀다.
- A8 **되돌리기:** 그 사이 시작된 방이면 미룸만 지우고 사람은 다시 넣지 않는다.
- A9 **강제 완료:** 미래 시각은 거절한다. 미룬 방의 강제 완료는 허용한다.
- A10 **일괄 처리:** 배정 저장 오류를 무시하지 않는다. 실패하면 실패로 돌려주고, 미룸 줄을 먼저 지워 배정이 사라지는 일이 없게 한다.
- A11 **제안 대상(2026-11-09):** 그날 일정이 살아 있는 **현장 멤버만**(활성 · `cleaning.work` 역할 — 직접 넣기 `isFieldMember` 와 같은 기준). 비활성 · 조직에서 빠진 사람의 신청 줄이 남아 있어도 제안(하루 · 월 · 「고정 인력 먼저」)하지 않는다(`suggestCandidates`). 이미 넣어 둔 앞날 배정은 지우지 않는다.
- A12 **제안 넣기 범위(2026-11-09):** 「제안대로 N개 넣기」 · 「고정 인력 먼저」는 화면에 보이는 건물(「내 건물」 거르기)만 넣는다. 화면이 범위를 보내고 서버가 같은 범위로 거른다(`suggestionsInProperties`) — 버튼의 N = 실제로 넣는 수.
- A13 **월 자동 제안 미리 보기(2026-11-09):** 미리 본 달에서만 보인다. 다른 달로 넘기면 사라지고, 돌아와도 다시 보이지 않는다(달이 바뀌면 미리 보기 상태 자체를 비운다). 반영은 미리 본 달로 보낸다(`stateForMonth`).
- A14 **되돌리기 날짜(2026-11-09):** 빼기 · 담당 바꾸기 · 미루기 · 처리 끝의 5초 되돌리기는 **그 동작을 한 날짜**로 보낸다. 토스트가 떠 있는 사이 다른 날로 옮겨도 원래 날을 고친다.
- A15 **취소 요청 수락(2026-11-09):** 요청이 아직 살아 있을 때만 — 따로 읽어 확인하지 않고 쓰기 조건(`cancel_requested_at is not null` · `cancelled_at is null`)으로 막아, 확인 뒤 쓰기 전에 알바가 거두는 경쟁도 막는다. 바뀐 줄이 없으면(`stale`) 배정도 지우지 않는다. 수락은 우리 조직에 이미 있는 요청 줄만 바꾸고 새 줄을 넣지 않아 현장 멤버 확인을 하지 않는다(그 사이 비활성이 된 알바의 요청도 받는다). 대신 취소는 멤버 확인을 그대로 한다. 알바가 거뒀거나 이미 취소된 날이면 아무것도 바꾸지 않고 「취소 요청이 이미 거둬졌거나 처리됐어요」.
- A16 **자동화 화면 「청소 명단」 방 추가 · 빼기(2026-11-09):** 추가는 위 표 「방 추가」 열과 같은 판단(`checkAddExtraRoom` — 청소 배정 「+ 방 추가」와 같은 함수). 빼기는 대기 방이고 아무도 배정되지 않았을 때만(`canRemoveExtraRoom`) — 배정 · 기록 · 미룸이 있으면 막고(미뤄서 목록에 안 보이는 방도 `loadAddBlockedRoomKeys` 로 막는다). 그 방이 그날 체크아웃 방이기도 하면 명단 줄을 빼도 목록 · 배정이 그대로라 배정이 있어도 뺄 수 있다. 막을 때는 청소 배정에서 먼저 정리한다(빼면 배정이 「취소됨」으로 남기 때문). 둘 다 열려 있는 배정 화면에 신호를 보낸다.
- A17 **사람을 받는 쓰기는 모두 현장 멤버 확인(2026-11-09):** 그날 출근 시각(`setDayStartTime`)도 넣기 · 옮기기 · 일정 취소와 같이 `isFieldMember` 로 본다. 멤버 확인은 시각을 넣을 때만 한다 — 시각 지우기는 비활성 · 조직에서 빠진 사람도 되고, 있는 신청 줄만 고치며 새 신청 줄을 만들지 않는다.

## 3. 어떤 기록을 어떻게 세나

「청소한 기록」 = **완료이고 처리 끝이 아닌 기록** 하나. 방 상태(대기 · 청소 중 · 1/2 끝남 · 끝남)는 `roomShareState` 하나.

| ID | 어디서 | 동작 |
|---|---|---|
| C1 | 근태 「청소 객실」 | 청소한 기록만. 취소 제외 |
| C2 | 교통비 후보 | 청소한 기록만. 취소 · 진행 중 제외. 이미 신청된 금액은 바꾸지 않는다 |
| C3 | 홈 · 대시보드 활동 피드 | 처리 끝 제외 |
| C4 | 모바일 기록 화면 | 처리 끝은 「처리 끝」으로 표시 |
| C5 | 비교표의 청소 수 | 자기 기록이 있는 방만 1개(나누지 않음) |
| C6 | 배지 · 대시보드 숫자 | 방 수로 센다. 사람 목록은 사람별 그대로 |
| C7 | 대시보드 건물 지도 | 1/2 끝남은 안 끝난 방, 처리 끝은 끝남 |
| C8 | PC 콘솔의 수기 · 밀려 온 2인 방 | 한 명만 끝내면 「1/2 끝남」 |
| C9 | 월 보기 미배정 · 월 제안 | 하루 보기와 같은 계산(끝난 방 · 미룸 · 처리 끝 제외) |
| C10 | 알바 「배정 없음」 판정 | 미룸 · 처리 끝 방은 미배정으로 세지 않음 |
| C11 | 「늦음」 판정 | 본인 기록으로 판단. 같은 방 동료의 시작은 내 시작이 아님 |
| C12 | 어제 기록을 `/mobile/cleaning` 에서 닫을 때 | 「청소했어요 / 못 했어요」, 소요 0초(서버가 끝내기 · 취소 모두에서 지킨다) |
| C13 | `/mobile/cleaning` 시작 | 청소 목록의 방은 서버가 다시 확인해 예약 취소면 막고, 수기 방은 허용. 수기 경로의 청소 종류는 화면 값 유지 |
| C14 | 유령 배정(그날 청소할 방 목록에 없는 배정 — 배정 뒤 예약 취소 · 날짜 변경) | 하루 보기는 「취소됨」 방으로 남기고 사람은 「배정 전」으로 위에 뜬다. 배정 수 · 신청자 「배정」 수 · 내 시프트 방 수와 상태 · 내일 방 수 · 월 보기 칸 · 비교표 배정 · 사람 달력 · 월 제안의 근무 일수에서 **세지 않는다**(`isGhostAssignment` · `liveAssignments` 하나). 그날 목록을 읽지 않은 날은 판단하지 않는다. **기록 있는 배정은 유령이 아니다** — 그 사람이 그날 그 방에 진행 중 · 완료 기록이 있으면 목록에 없어도 살아 있는 배정으로 센다(「기록 있는 사람은 빠지지 않는다」와 같은 원칙, 지난 날 비교표 · 사람 달력에서 실제 청소한 방이 빠지지 않게). 한 날 판단(알바 신청 빼기 · 취소 요청 · 관리자 월 칸 신청 빼기)도 서버 공용 `loadLiveAssignmentsOfDay` 하나 — 체크인 정보는 읽지 않는다. 하루 보기 이번 달 근무 일수도 월 제안과 같은 기준 — 단, 「근무 일수 적은 사람」 규칙이 켜져 있고 제안할 방이 있고 고를 사람이 둘 이상일 때만 읽는다(`needsMonthWorkDays`), 제안 대상 사람 배정이 있는 날 범위만. 한 사람 그날 몫 · 건물은 보드와 제안이 같은 함수(`personDayWork` — 기록 있는 방은 목록에 없어도 1인 방 무게로 든다), 기록 인자는 필수. 오늘 내 방 「취소된 날」 표시도 살아 있는 배정 수로 본다. 유령 배정만 남은 날은 알바가 신청을 뺄 수 있고 취소 요청은 걸지 않는다(줄은 관리자가 정리) |
| C15 | 사람 달력 「일한 날」 · 「기록 없음」 | 청소한 기록(`isCleanedRecord`)이 있는 날만 일한 날. 취소 · 처리 끝은 기록이 아니고, 시작만 하고 끝내지 않은 기록은 방 줄에 시작 시각만 보인다(`indexPersonRecords`) |

## 4. 하루 몫 상한

| ID | 규칙 |
|---|---|
| L1 | 작은 방 1, 큰 방(보통 인원 2명 이상) 1.5, 한 사람 상한 3 |

## 결정 기록 (2026-11-04)

1. R9: 미룬 기간 중 새 체크아웃은 정상 방 + 시작 허용.
2. A7: 일정 취소는 청소 중이면 막고, 끝낸 방 배정은 남긴다.
3. C2: 교통비 후보는 완료 기록만. 건물에 갔지만 「못 했어요」로 닫은 날은 직접 입력한다.
4. L6: 상한은 제안에만 강제하고, 직접 넣기는 확인 창만.

## 결정 기록 (2026-11-09 · 점검 D)

1. A11: 제안 대상에서 비활성 · 조직에서 빠진 사람을 뺀다. 이미 들어간 앞날 배정은 지우지 않는다(보드에는 지금 비활성 표시가 없다 — 사용자 확인 대기).
2. A16: 자동화 화면 방 빼기는 배정이 든 방을 막는다(배정 쪽에는 수기 방 빼기가 없고, 빼면 배정이 「취소됨」 유령이 되므로).
3. C14: 유령 배정만 남은 날 알바가 신청을 빼도 남은 배정 줄은 지우지 않는다 — 관리자가 「취소됨」 방에서 정리한다.
4. C15: 시작만 하고 끝내지 않은 날은 「일한 날」이 아니라 「기록 없음」으로 보인다(청소한 기록 기준 하나).
