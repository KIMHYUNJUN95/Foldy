# 37 · 시프트 신청 · 청소 배정 (기획 중)

> 상태: **기획 초안 (2026-10-20)** — 사용자와 함께 다듬는 중. 코드 작업은 아직 시작하지 않았다.
> 「정할 것」 표가 다 채워지면 시안 → 승인 → 구현 순서로 간다.

## 1. 왜 만드나

지금 청소 배정은 외부 서비스 **Hotelsmart** 에서 한다. Hotelsmart 는 원래 **무인 체크인**(건물 앞 태블릿 · 여관업법상 숙박자 명부 ·
본인 확인) 때문에 쓰는 서비스이고, 청소 배정은 거기 딸린 부가 기능이다.

- **청소 쪽에서 실제로 쓰는 것은 하나** — 그날 시프트를 신청한 알바생을 그날 체크아웃 객실에 배정하는 것.
- 청소 완료 상태는 Hotelsmart 에서 다루지 않는다. 외부 API 도 없다(우리가 쓰는 외부 API 는 Beds24 하나).
  → **청소 배정을 끊어도 체크인 쪽에 영향이 없다.**
- 문제: 쓰기 불편하고 버그가 많다. 알바생마다 **개인 시프트 URL** 을 만들어 주고, 각자 그 페이지에서 가능한 날을 신청하면,
  관리자가 본계정에서 신청자를 하나씩 방에 배정한다. **이 구조는 따라 하지 않는다.**
- Foldy 에는 재료가 이미 있다: 오늘 청소할 방(퇴실 기준) · 수기로 더한 방(`cleaning_list_extra_rooms`) · 현장 청소 타이머/기록 ·
  Slack 청소 · 셋팅 명단(`docs/product/36-automation-control.md` ②) · 출근 기록. 빠진 것은 **「누가 언제 나오나」와 「누가 어느 방」** 둘이다.
  지금 Slack 명단 담당자는 사람이 손으로 넣는다(`cleaning_list_assignees`, Hotelsmart 약관상 자동 수집 안 함).

### 범위 밖

- 무인 체크인 · 숙박자 명부 · 본인 확인 — **Hotelsmart 그대로**.
- Hotelsmart 와 데이터 주고받기 — API 가 없으므로 하지 않는다.

## 2. 지금 일하는 방식 (사용자 확인 2026-10-20)

| 항목 | 지금 |
| --- | --- |
| 일하는 사람 | 우리 회사 소속 알바생. **Foldy 개발이 끝나면 전원 Foldy 에 가입**시킨다(지금은 아직 계정 없음) |
| 근무 형태 | **시프트제** — 희망 휴무가 아니라, 알바생이 **일할 수 있는 날을 날짜마다 신청**한다 |
| 출근 시각 | 정해져 있다(가끔 예외). 시간대 선택은 필요 없다 |
| 배정 시점 | **매일** 한다. 예약이 매일 들어와 그날 방이 계속 바뀐다. **월말에 다음 달 배정**을 하느라 그때가 가장 바쁘다 |
| 배정 방식 | 그날 시프트 신청자 → 그날 체크아웃 객실. 유동적이라 **방을 수기로 추가해서 배정**하는 경우도 있다 |

## 3. 핵심 아이디어 — 「사람 정하기」와 「방 나누기」를 떼어 낸다

Hotelsmart 의 월말이 바쁜 이유는 **아직 확정되지 않은 한 달 치 방을 미리 사람에게 붙이기** 때문이다. 예약은 매일 바뀌니
월말에 붙인 방은 매일 다시 고쳐야 한다. 그래서 두 단계로 나눈다.

| | 언제 | 무엇을 | 누가 |
| --- | --- | --- | --- |
| **① 시프트 확정** | 월말(다음 달 전체) + 수시 | 날짜마다 **누가 나오나** | 관리자 |
| **② 방 배정** | 매일(전날 저녁 자동 + 당일 손보기) | 그날 나오는 사람에게 **어느 방** | 대부분 자동, 관리자는 예외만 |

- 월말에는 ① 만 한다 — 방이 아니라 **사람 수**를 맞춘다. 날짜마다 「예상 청소 방 수」(이미 들어온 예약의 퇴실)와
  「신청자 수」를 나란히 보여 주고, 모자라거나 남는 날을 색으로 표시한다.
- 방은 ② 에서 그날 확정된 사람에게 **자동으로 나눈다.** 관리자는 결과를 보고 끌어다 옮기거나 고정만 한다.
- 예약이 바뀌면(새 퇴실 · 취소 · 연장) 그날 배정이 **다시 계산**되지만, **사람이 손댄 방은 고정**돼 움직이지 않는다.

## 4. 화면 (초안)

### 4-1. 시프트 신청 — 모바일 (알바생)

- 개인 URL 없음. **Foldy 앱에 로그인한 그대로** 「내 시프트」에서 달력을 열고 일할 수 있는 날을 누른다.
- 신청 / 취소는 마감 전까지 자유. 마감 뒤에는 관리자에게 요청(정할 것 Q1).
- 확정되면 날짜에 「확정」 표시. 「오늘 내 방」(4-4)으로 이어진다.

### 4-2. 시프트 확정 — PC (관리자, 월 단위)

- 날짜 × 사람 표. 칸 = 신청 / 확정 / 미신청. 누르면 확정 ↔ 신청.
- 날짜 머리에 **예상 방 수 · 필요 인원 · 확정 인원**, 모자라면 빨강, 남으면 회색.
  필요 인원 = 예상 방 수 ÷ 1인당 기준 방 수(정할 것 Q3).
- 신청자가 넘치는 날 고르는 기준(정할 것 Q4).
- 관리자가 대신 넣기 — 계정 없는 기간 · 전화로 받은 신청(정할 것 Q6).

### 4-3. 방 배정 — PC (관리자, 매일)

- 날짜 고르기 → 왼쪽 그날 청소할 방(퇴실 + 수기 추가), 오른쪽 그날 확정된 사람별 칸.
- **자동 나누기**: 같은 건물끼리 묶고(이동 줄이기) 1인당 방 수를 고르게. 결과에서 끌어다 옮기기 · 고정.
- **방 수기 추가**: 지금의 `cleaning_list_extra_rooms`(퇴실 없는 연박 청소 등)를 그대로 쓴다 — 추가한 방도 배정 대상.
- 바뀐 것 표시: 배정 뒤 새로 생긴 방 · 사라진 방 · 사람이 빠진 경우를 위에 한 줄로.
- 결과가 **Slack 청소 · 셋팅 명단 담당자**로 그대로 나간다 → `cleaning_list_assignees` 수기 입력이 없어진다.

### 4-4. 오늘 내 방 — 모바일 (알바생)

- 앱을 열면 배정된 방만 순서대로. 누르면 지금의 청소 시작(타이머)으로 이어진다.
- 배정이 바뀌면 목록이 바뀐다(알림은 「막바지 일괄」 규칙 — 지금은 붙이지 않는다).

### 4-5. 예정 vs 실제 — PC (나중)

- 확정 시프트 ↔ 실제 출근, 배정 방 ↔ 실제 청소 기록. 미시작 방 · 미출근을 한눈에.

## 5. 권한 (초안)

| 할 일 | 누가 |
| --- | --- |
| 시프트 신청 · 내 시프트 · 오늘 내 방 | 현장 소속 전원(알바 포함) — 본인 것만 |
| 시프트 확정 · 방 배정 · 방 수기 추가 | 관리자 쪽(새 권한 키, 예: `cleaning.assign`) — 역할 범위는 정할 것 Q7 |

서버에서 막는다(CLAUDE.md §6). 알바는 다른 사람 신청 · 배정을 볼 수 없다(정할 것 Q8 — 같은 날 동료 이름은 보여 줄지).

## 6. 옮겨 가는 순서

1. 시프트 신청 · 확정 → 2. 방 배정 + Slack 명단 연결 → 3. 오늘 내 방 → 4. 예정 vs 실제.
- 1~3 이 되면 Hotelsmart 의 청소 배정을 끊을 수 있다(체크인은 계속 사용).
- **처음 2주는 한 건물만 Hotelsmart 와 같이 돌린다** — 아침 배정이 한 번 멈추면 그날 청소가 꼬인다.
- 전원 가입은 개발 완료 뒤. 그 전 시험 기간은 관리자가 대신 넣기(Q6)로 돈다.

## 8. 기록

- 2026-10-20 — Beds24 에도 청소 배정 흉내(유닛 상태 = 청소 담당자 이름 + 맞춤 보고서)가 있지만 날짜별 배정 · 현장 연결이
  없어 대안이 못 된다고 판단. Hotelsmart 청소 배정을 Foldy 로 옮기기로 하고 기획 시작. 체크인은 Hotelsmart 유지.
